# 上传首尾帧图片导致「整个导演台崩掉」——根因与修复

**症状（用户原话）**：在没有清理的时候，额外上传图片，会导致整个导演台都崩掉了。

**结论**：不是前端渲染问题，是**后端死循环把 ComfyUI 整个事件循环占死了**。
aiohttp 单线程事件循环，一个请求里转起 `while True`，结果就是：导演台所有
接口全部超时、ComfyUI 页面本身也不响应、只能杀进程。所以表现出来就是
"整个导演台崩掉了"。

---

## 一、根因：`while lbl in taken: lbl = f"{base}{n}"[:24]`

`library.py::store_to_project`（`mirror_to_project` / `projects.py::import_asset`
同样写法）给新素材挑标签时是这么写的：

```python
lbl  = (str(label or "").strip() or os.path.splitext(cand)[0])[:24] or "素材"
base, n = lbl, 2
while lbl in taken:
    lbl = f"{base}{n}"[:24]      # ← 当 base 已满 24 字，截断后恒等于 base
    n += 1
```

前端传的 `alias` 是**文件名主干 `.slice(0, 24)`**（`h3_director.js:
openFramePicker`）。于是：

- 只要文件名主干 ≥ 24 字，`base` 就是满 24 字；
- 再传一张**同前缀**的图（序列帧 `…_01.png` / `…_02.png` 就是这种），
  `alias` 完全相同 → `lbl in taken` 成立；
- 循环体里 `f"{base}{n}"[:24] == base`，`lbl` 永远不变 → **死循环**。

### 实测复现（服务端真跑）

```
POST /h3chain/library_upload  alias="a"*30   → 200  label="a"*24
POST /h3chain/library_upload  alias="a"*30   → 25s 无响应（HTTP 000）
                                                ↑ 服务端事件循环已死
```

中文用户文件名很容易凑满 24 字（`角色设定_阿依_正面_全身_白色连衣裙_白天_01`），
所以这不是理论问题 —— **连传两张同名前缀的图就中**。

---

## 二、修复

### 1) 后端：统一走"先留位再递增"的唯一化工具

新增 `library.unique_label(base, taken, cap=24)` 与 `library.unique_filename(dir, want)`
（`projects.py` 里同款 `_unique_label` / `_unique_filename`）：

```python
b = str(base or "").strip()[:cap] or "素材"
if b not in taken:
    return b
stem = b[:max(1, cap - 3)]        # 关键：先截到 cap-3 给后缀留位
n = 2
while n < 10000:
    cand = f"{stem}{n}"[:cap]
    if cand not in taken:
        return cand
    n += 1
# 兜底：时间戳，绝不再循环
```

替换点：`library.py` 的 `mirror_to_project` / `store_to_project` / `store_to_finals`，
`projects.py` 的 `import_asset`。文件名唯一化（`while os.path.exists`）也统一换成
带硬上限的 `unique_filename`。

### 2) 前端：`pushPoolAsset` 同样口径

`h3_director.js::pushPoolAsset` 原来也是 `lbl = base + n` 之后再整体截断的写法，
改成先截 21 再递增（与后端 cap-3 同口径），并加硬上限。

### 3) 上传链路不再留下"卡住"的界面

`openFramePicker` 的「＋ 上传一张」：

- 加 `uploading` 并发闸门（连点/重复 `onchange` 只跑一次，避免两次写锚点互相踩）；
- `Promise.race` 45s 超时兜底：后端万一再被卡住，明确报
  "后端 45 秒无响应（ComfyUI 可能已卡死）"，而不是永远停在"上传中…"；
- `finally` 里恢复按钮态，`closeOverlay()` 兜 `overlay.remove()`。

### 3.5) 前端数据请求带超时

`fetchJson`（manifest 读取，被 `hydratePool` / `openFramePicker` 依赖）改为走
`fetchWithTimeout(url, 12000)`（`AbortSignal.timeout`，老浏览器退回
`AbortController` + `setTimeout`）。服务端卡死时至少 12s 后按失败返回，
不会把调用方一起挂住。

### 4) 导演台不再被单点异常打死

以前 `updateDesk` 里任何一区抛异常 → `refresh()` 整体失败 → **之后每次刷新都在
同一处摔倒** → 左栏空、中栏不更新、侧栏退化成报错卡 = 用户看到的"台子崩了"。

- 新增 `runZone(name, fn)`：项目与链 / 段落流水线 / 链参数 / 实验功能 /
  二采放大 / 成片历史 / 页脚各自 try/catch，一区挂掉只跳过该区；
- 顶栏新增"⚠ 渲染异常（N）"徽标（hover 看区名与错误），异常不再只进 console；
- `buildCardsSafe(data)`：段卡构建抛异常时渲染一张错误卡，不牵连整条流水线。

### 5) 顺带

- 选图弹窗「＋ 上传一张」的 title 不再写"全局库一份 + 项目一份"——后端
  `dest=project` 就是**只落项目**（早期会顺手复制进全局库，已按反馈去掉）；
  跨项目复用是素材库里显式的「存入全局库」。
- 后端其余 `while` 全部复核过一遍，均有界：
  `transcode_queue.claim()` 会把任务置 running（队列必然排空）；
  采样重摇循环有 `attempt >= reroll_max + motion_extra` 上界；
  `cond_cache` / 文件名 `_2/_3` 递增都是单调推进。

## 四、排查笔记（下次别再绕远）

- jsdom 里**跑不出**这个 bug：它卡的是服务端事件循环，前端只会表现为"请求不返回"。
  排查此类"整台崩掉"先 `curl` 一下接口看是否超时，比在前端代码里找异常快得多。
- 同类坑的通用形状：**"在循环体里做截断"**。凡是
  `while 冲突: 候选 = f(基础, n)[:cap]` 都要先给后缀留位。

## 五、续报：清除首尾帧后「具象化不跟着清除」+ 对齐指令里的图片编号

### 1) 段卡签名漏了段级 frame_img（真 bug）

`cardsSignature` 的 `frames` 只放了**全局** `ds.first_frame` / `ds.end_frame` 两个
旧槽位，**没放段级 `seg.frame_img`**。段级锚是现在唯一的入口，于是：

改锚 → 签名不变 → `renderCenterColumn` 判定"没变化"→ **整张段卡不重建** →
具象化面板顶部的对齐指令预览、模式判定行、锚点区全部停在旧状态。
只有切屏（签名因别的原因变化）才刷新 —— 与之前"切一下屏又好了"是同一个洞。

修：`frames` 追加各段 `${frame_img.first}/${frame_img.end}`。
回归：`tests/js/frame_anchor_sync_check.js`（把签名改回旧版会红 3 条，已验证）。

### 2) 对齐指令里的"Picture 1"是什么

官方 I2VA / FL2VA / L2VA 的对齐指令是**固定英文句**，只能写 `<Picture k>` 编号，
**不能写文件名**（见 `tools/h3_prompt_expander/references/h3-dialect.md` §1.2）。

编号 ↔ 锚的映射（与后端 `prompts.compile_segment` 同口径）：

| 模式 | 首帧锚 | 尾帧锚 |
|---|---|---|
| I2VA | `<Picture 1>` | — |
| L2VA | — | `<Picture 1>` |
| FL2VA | `<Picture 1>` | `<Picture 2>` |
| T2VA / Ref2VA | 无对齐句 | 无对齐句 |

**不会串号**：本插件的首尾帧锚走 keyframe latent 注入（`nodes.py`
`seg_head_img_latent` / `seg_end_img_latent`），**不进 `compile_refs` 编号**；
而只要段里带参考素材就会被判成 Ref2VA，Ref2VA 根本不生成对齐句。
所以对齐指令里的编号在本段内唯一指向你传的那张图。

### 3) 为了"能对上号"加的两处显示

- 首尾帧按钮：加**缩略图** + `P1` / `P2` 编号徽标（光看文件名分不清是哪张）；
- 具象化面板「输出结构」下新增**锚点对照**行：
  `<Picture 1> = 首帧图 · A.png`，并说明 Ref2VA 不生成对齐句。

## 六、锚定到底生不生效（端到端核实）

**结论：生效，而且不依赖提示词文本。**

真正把图钉进画面的是**数据层**，不是那句英文：

```
ds.segments[i].frame_img
  → nodes.py _parse_frame_imgs()
  → _frame_img_latent()：_load_input_image → VAE encode
  → seg_head_img_latent[i] / seg_end_img_latent[i]
  → _apply_guide(cond, guide, length, head_kf_latent=…, tail_kf_latent=…)
  → 官方 minimax_keyframes：**每一步都重新注入，从不被去噪**
```

运行报告里会打印「段级首尾帧参考图：段N头锚 · 段M尾锚（身份锚 keyframe 注入）」。
提示词里那句对齐指令只是**文本层**的辅助描述。

所以：
- **AI 提示词优化冲不掉锚** —— 它只改 `prompts[idx]`，不动 `segments[idx].frame_img`；
  优化完前端还会按锚把对齐行补回去（`resyncAlignmentLines`）。
- **优化时后端知道模式** —— `optTaskForMode()` 返回 `defaultV2Mode()`，
  有锚 → I2VA/FL2VA/L2VA 走 base 三段式规则，不会误写成 Ref2VA 六段式。

### 顺带修掉的丢锚 bug：读档不还原 frame_img

`flushPrompts` 会把 `frame_img` 写进 `mf.seg_fields`，但读档用的
`restoreSegField()` **漏了这一项** → 切一次项目 / 读一次档，整链段级锚全被清成空，
而段卡上还显示着旧文件名（签名里有 frame_img）—— "看着有锚、跑起来没锚"。

修：`restoreSegField` 补上 frame_img 还原。
回归：`tests/js/frame_anchor_persist_check.js`（回退修复会红 1 条，已验证），
同时锁住「优化不冲锚 / 落盘带 frame_img / 贴总提示词不冲锚」三条。
