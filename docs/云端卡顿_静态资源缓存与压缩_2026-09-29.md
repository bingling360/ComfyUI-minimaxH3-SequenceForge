> 在**公网链路 × ComfyUI 的响应策略**。`/object_info` 6.4MB 裸传（81d03fa 已修）只是

## 2. 修了什么

### 2.1 新中间件 `_static_cache_middleware`（`routes.py`）

只对 **`.js`/`.css` 的 `FileResponse`** 生效，三件事：

1. **接管 Cache-Control**（在链路内层、先于 `cache_control` 执行，它的
   `setdefault` 不再补 no-store）：
   - `/assets/`（前端 vite **内容哈希**文件名，内容永不变）
     → `public, max-age=31536000, immutable`，有效期内**零请求**；
   - 其余（`/extensions/` 下插件文件，URL 固定内容会随更新变）
     → `no-cache` 每次协商重验，命中即 **304 空响应**（158ms RTT，不传包）。
2. **兜底 ETag + 304 短路**：格式与 aiohttp 原生一致（`mtime_ns:x-size:x`），
   老 aiohttp 的 FileResponse 没有协商逻辑时由这里接 `If-None-Match`。
3. **冷启动 gzip**：客户端接受时对 200 的 .js/.css 开压缩并补
   `Vary: Accept-Encoding`（FileResponse 自动退到分块流式压缩路径）。

挂载：`register()` 里 `enable_static_cache_policy(app)`，与压缩中间件同一纪律
（**原地 append** FrozenList、异常全吞、签名老实写 `(request, handler)`）。

预期账（下行 2.5MB/s、RTT 158ms 口径）：

| 场景 | 改前 | 改后 |
|---|---|---|
| 刷新页面（前端 JS ~15–30MB + 插件 770KB） | 全量明文重传，**10s+** | `/assets` 命中 0 请求；插件 JS 304 空响应（≈5×158ms）；插件更新后的首次加载 gzip 后 ~¼ |
| 首次打开（冷浏览器） | 全量明文 | gzip ~3–4× |
| 素材库翻一页（60 缩略图） | 60 次全量重拉 | 一天内 **0 请求**；过期后协商 304 |

### 2.2 素材库缓存头（`routes.py` handler 直改）

- `lib_thumb`：`Cache-Control: public, max-age=86400` —— 缩略图入库即生成、
  按 id 内容不变；URL 无图片扩展名，`cache_control` 本来对它不设头。
- `lib_raw` inline 预览：`public, max-age=3600` —— 原文件有被重传覆盖的可能，
  只给 1 小时；过期后 FileResponse 自带 ETag 协商，重传过的新文件自然 200。
  `download=1` 分支不动。

## 3. 测试与跑法

`tests/test_static_cache_policy.py`（行为测试，真 aiohttp + 真 FileResponse，
**复刻了 ComfyUI 的 no-store 分支挂在外层**，验证内层确实压住它）：

- 扩展 JS：`no-store` → `no-cache` + ETag；`If-None-Match` 命中 → 304 空响应；
  ETag 对不上 → 200 新内容。
- `/assets/*.js` → `immutable` 长缓存。
- gzip：`Content-Encoding: gzip` + `Vary: Accept-Encoding`。
- 非 js/css 的 FileResponse（缩略图）：中间件不碰，处理器自己的头原样在。
- 处理器 404 的 .js：原样放行，不许变 5xx。
- 绊线：缓存头必须**强设**、必须**原地 append**、ETag 格式必须与 aiohttp 原生一致。
