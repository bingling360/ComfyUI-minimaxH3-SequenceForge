## 0. 一句话结论

分段提示词的**主库是节点上的「导演台状态」控件**（一个 JSON 字符串，按位存进
`widgets_values[27]`），跟着**工作流文件**走；项目文件夹 `manifest.json` 只是
**1.5s 防抖的异步副本**，且切工作流时**没有任何自动回灌**。

所以「切工作流丢提示词」不是一个 bug，而是**三条链路各有一个断点**的叠加：
进控件（350ms 窗口）→ 进文件（是否保存）→ 进备份（1.5s + 目录有效）。
再叠加迁移层按位取错和迟到写回，才会出现「有时丢、有时不丢」。

`flushPendingEdits()` 全仓**只有 `switchProject` 一个调用点**（`:7332`）。

## 2. 六个丢失路径（按严重度排序）

### L1 未保存就切走 —— 必然
`app.loadGraphData` 被包装（`:12821`），换图后控件值完全来自目标文件。
没 Ctrl+S 的编辑不在文件里；若目录为空（自带默认工作流 `存档目录=""`，`h3_default_workflow.js:604`），
`flushPrompts` 直接返回，磁盘也没有副本。

### L2 350ms 窗口没提交 —— 高频
切图会整体替换 DOM，`blur` 不一定触发；`flushPendingEdits()` 又只在切项目时调用。
最后一段（甚至整段未失焦的）文字压根没进 `ds`，随旧图一起消失。

### L3 迁移层按位取错 + 静默回退 —— 隐蔽，整份丢
`migrateGraphWidgets`（`:1749`）在**每次**载入前跑；`isCurrentWidgetLayout`（`:1688`）只看形态，
且第一条分支只要求「长度 30 + 第 0 位是字符串」，**不再检查第 27 位**。
→ 旧 25/31/35 值布局、或被写坏过的存档，会把别的控件值顶到「导演台状态」
（可能是数字 `1.0` 或字符串 `"match"`）；`getDs` 的 `JSON.parse` 失败后
**静默 `catch → defaultDs()`**（`:2823`），`prompts` 变 `[""]`，界面全空、不报错。
（2026-09-20 出过同类事故，见 `:1671` 注释。）

### L4 迟到写回盖掉备份 —— 最伤
`schedulePromptFlush`（`:7332`）不记 node/dir，1.5s 后才 `findNode()` + 读它的目录。
切到**存档目录同名**的另一份工作流后，定时器到点读到新节点的空 `prompts`，
写进同一个项目 manifest —— 磁盘上唯一那份兜底也被冲掉。
`_uiGen`（`:3954`）只在 `switchProject` 里自增（`:7344`），切工作流不作废任何挂起任务。

### L5 「⚡ 一键载入配套工作流」—— 必然
`loadDefaultWorkflow`（`:3912`）确认后直接 `loadGraphData` 换画布，
**切换前不 flush、不搬词**，只弹一句「未保存的画布修改会丢失」。

### L6 多个 H3 节点 —— 条件
`findNode()` 取 `app.graph._nodes` 里**第一个**（`:1592`）。含两个导演台节点的工作流，
第二个上的提示词「看不见」，且后续所有写入/落盘都只走第一个。

### 2.7 附：自动恢复是死代码
`:7663` 那段「采纳存档提示词进导演台状态」判据是 `!plan || !plan.length`，
而 `planFromDs`（`:6738`）永远至少返回 1 段 → 条件恒假。
**结论：当前不存在「节点空了自动从项目恢复」这条路。**

## 3. 设计原则

1. **控件是主库这一点不改**（改存储形态会牵动 frozen 测试与后端 `parse_state`）；
   要做的是给主库加**两道保险**：切图前落盘、按名字（非按位）快照。
2. **静默降级一律改成留证 + 可见**：解析失败不许悄悄变空。
3. **任何写入都必须绑定「发起时的 node + dir」**，不许 1.5s 后再去猜当前节点。
4. **自动恢复只给「确定是我们丢的」场景**（properties 快照）；其余用横幅一键恢复，避免复活用户故意清空的内容。

## 4. 分阶段方案

### P0-1 换图前落盘钩子（修 L1 / L2 / L4 的作废）

**函数**：`setup()` 里对 `app.loadGraphData` 的包装（`:12821`）

```js
app.loadGraphData = function (data, ...args) {
    const oldNode = findNode();
    if (oldNode) {
        try { flushPendingEdits(); } catch (e) { /* 单条失败不阻断换图 */ }
        const oldDir = getDirValue(oldNode);
        if (oldDir) {
            /* flushPrompts 是 async，但 body 在第一个 await 之前就已序列化完成 →
               这里不 await 也安全（拿到的是旧节点的数据，不会被新图污染） */
            flushPrompts(oldNode, oldDir);
        }
        _uiGen += 1;                    // 作废挂起的 350ms 写回
        clearTimeout(promptFlushTimer); // 作废挂起的 1.5s 落盘（必须在 flushPendingEdits 之后）
    }
    const migrated = migrateGraphWidgets(data);
    /* …原逻辑… */
};
```

要点：
- **不要**把包装器改成 async / 不 await `origLoadGraphData` 以外的逻辑，避免影响前端调用约定。
- `flushPrompts` 前先 `flushPendingEdits()`，否则 350ms 窗口的内容不进 body。
- `_uiGen++` 只在 `oldNode` 存在时做（首次页面载入不自增）。

**影响面**：每次换图会多一次 `save_prompts`（仅当目录非空且内容有变，见 P0-5 去抖）。
**测试**：`graph_switch_flush_check.js`。

### P0-2 `schedulePromptFlush` 绑定 node/dir（修 L4）

**函数**：`schedulePromptFlush`（`:7331`）；调用点 `setPromptText:2871`、`addPromptSegment:2883`、
`removePromptSegment:2895`、`applyPromptEdit:3025`

```js
let promptFlushTimer = 0;
let promptFlushJob = null;

function schedulePromptFlush(node) {
    const n = node || findNode();
    if (!n) return;
    const dir = getDirValue(n);
    promptFlushJob = { node: n, dir };            // 发起时快照，绝不 1.5s 后重算
    clearTimeout(promptFlushTimer);
    promptFlushTimer = setTimeout(() => {
        const job = promptFlushJob;
        promptFlushJob = null;
        if (job) flushPrompts(job.node, job.dir);
    }, 1500);
}
```

调用点全部改成 `schedulePromptFlush(node)`。
`switchProject` 里 `clearTimeout(promptFlushTimer)` 后顺手 `promptFlushJob = null`。

**收益**：迟到写回只会写给**旧节点 + 旧目录**（幂等、不跨项目），L4 消失。
**测试**：`prompt_flush_binding_check.js`。

### P0-3 迁移层：ds 槽位独立校验 + 非破坏性兜底（修 L3）

**函数**：`isCurrentWidgetLayout`（`:1688`）、`remapOldWidgetValuesToCurrent`（`:1719`）、
`migrateGraphWidgets`（`:1749`）

新增两个纯函数（便于单测）：

```js
/** 只认能解析且像导演台状态的字符串；数字/空串/别的控件值一律不认 */
function parseDsValue(v) {
    if (typeof v !== "string") return null;
    const s = v.trim();
    if (!s || s[0] !== "{") return null;
    try {
        const o = JSON.parse(s);
        return (o && typeof o === "object" && (Array.isArray(o.prompts) || Array.isArray(o.segments)))
            ? o : null;
    } catch (e) { return null; }
}

/** 按优先级找真身：第 27 位 → properties 快照 → 全数组倒扫（只认字符串） */
function pickDsJson(wv, props) {
    if (parseDsValue(wv[27])) return wv[27];
    const snap = props && props.__h3_ds;
    if (parseDsValue(snap)) return snap;
    for (let i = wv.length - 1; i >= 0; i -= 1) {
        if (i !== 27 && parseDsValue(wv[i])) return wv[i];
    }
    return "";
}
```

改造判据（三步）：

1. **长度 30 且第 0 位是字符串** → 视为当前布局，但**单独修第 27 位**：
   `const fixed = pickDsJson(wv, n.properties); if (fixed !== wv[27]) { wv[27] = fixed; warn }`
   —— **绝不因为 ds 槽位坏掉就整条重排**（这是当前最危险的行为）。
2. **31 值** → 仍走「只砍 idx28」，砍完再对第 27 位做一次 1 的校验。
3. **25/35 等旧布局** → 重排后，`tailDs` 必须过 `parseDsValue`；不过则用
   `pickDsJson(原 wv, n.properties)` 兜，仍拿不到就写 `""` 并记 `__h3_ds_missing` 标记（供 UI 解释）。
4. `isCurrentWidgetLayout` 第一分支补一条：`wv[27]` 是数字/对象时**不要**直接 return true，
   交给 1 的修复分支（否则「已被写坏的存档」永远修不回来）。

**测试**：`ds_slot_repair_check.js`（30 值坏槽 + 快照 / 无快照 / 35 值 / 25 值 / 正常存档不被动）。

### P0-4 `getDs` 失败不再静默（修 L3 的「看不见」）

**函数**：`getDs`（`:2622`）

```js
} catch (e) {
    const raw = String(w.value || "");
    _dsBroken = { nodeId: node.id, error: String(e), len: raw.length };
    try {
        node.properties = node.properties || {};
        node.properties.__h3_ds_raw = raw.slice(0, 512 * 1024);   // 留证，防被后续写回覆盖
    } catch (_) { /* 属性写不进不影响主流程 */ }
    console.error("[h3-director] 导演台状态解析失败（原文已存 properties.__h3_ds_raw）", e);
    return defaultDs();
}
```

配套：导演台顶栏加一条常驻红条「导演台状态损坏（N KB 原文已保留）· [导出原文]」，
点了把 `__h3_ds_raw` 存成项目 `texts/` 下的文件。
**关键**：先留证，再允许任何写回 —— 否则第一次 UI 交互就把原文换成 `defaultDs`，取证彻底没了。

**测试**：`ds_broken_banner_check.js`。

### P0-5 落盘去重（防写放大）

`flushPrompts` 里对 body 做一次签名（`prompts.join("\u0000")` + 段字段 JSON 的简单哈希），
与模块级 `_lastFlushSig` 相同则**跳过本次 POST**（不动 `revision`）。
理由：P0-1 会让「每次换图」都可能触发一次落盘，而 `save_prompts` 每次 `revision += 1`，
无脑发会让 manifest revision 疯涨、也可能踩乐观锁。

### P1-1 `properties.__h3_ds` 快照 —— 按名字的第二道保险

**函数**：`onSerialize` 包装（`:12780`，已有 `__h3_out_intents` 的同款先例）

```js
d.properties.__h3_ds = safeDsSnapshot(this);   // 上限 512KB，超了跳过并 warn
d.properties.__h3_ds_ver = H3D_VER;
```

- `properties` **不按位**、不随控件增删漂移，是当前架构里唯一稳的「按名字」通道。
- 载入侧在 P0-3 的 `pickDsJson` 里读取。
- 代价：工作流 JSON 里提示词存两份。上限 512KB 兜住极端；正常 12 段 × 1KB ≈ 24KB，可接受。

**测试**：`ds_prop_snapshot_check.js`（序列化含快照 / 载入优先快照 / 超限跳过）。

### P1-2 项目存档一键恢复横幅（修 §2.7 死代码留下的洞）

**函数**：新增 `adoptManifestPrompts(node, mf)`，从 `switchProject:7393-7405` **抽出来**
（两处必须同一口径，不能各写一份）；`:7663-7696` 的死分支**删除**。

打开导演台 / 换图后 `refresh()` 判定：

```js
const ds = getDs(node);
const empty = !(ds.prompts || []).some((t) => String(t).trim());
const hasSaves = (mf?.prompts || []).some((t) => String(t).trim());
if (empty && hasSaves) showRestoreBanner(node, mf);   // 不自动覆盖，给一个按钮
```

横幅文案：「本项目存档有 N 段提示词，当前画布为空 · [恢复到画布] [忽略]」。
恢复动作 = `adoptManifestPrompts` + `setDs`（`refs` 由 `syncRefsFromText` 重新派生，与既有口径一致）。

**为什么不用自动**：节点为空也可能是用户刚「清空」过；自动复活会变成反向 bug。
唯一允许自动的场景是 P1-1 的快照命中（那确定是我们丢的）。

### P1-3 「一键载入配套工作流」带词搬家（修 L5）

**函数**：`loadDefaultWorkflow`（`:3912`）

1. 换图前：`flushPendingEdits()` + `flushPrompts(oldNode, oldDir)`；
2. 换图后：若新节点 `prompts` 全空、旧节点有内容 →
   `prompts / segments / ref_assets / inserts` 搬过去，并把 `存档目录` 一起带回去；
3. `LED` 明确写「已带过来 N 段提示词（模板自身为空）」；
4. `confirm` 文案补一句「当前提示词会自动带过来」。

### P2-1 多节点绑定（修 L6）

- 模块级 `_activeNodeId`；`findNode()` 优先返回它（不在图上则回落第一个）；
- `openDesk` / 段卡任意交互时 `_activeNodeId = node.id`；
- 节点数 > 1 时顶栏出一个 chip：「导演台绑定 #12 ▾」，可切换；
- 所有写入（含 `flushPrompts`）只走绑定节点，绝不「第一个」。

## 7. 风险与回滚

| 风险 | 处置 |
|---|---|
| 包装器改 async 破坏前端约定 | 不改 async；`flushPrompts` 火忘（body 已同步序列化） |
| 每次换图都写盘 → revision 涨 / 乐观锁冲突 | P0-5 签名去重；无变化不发 |
| `properties.__h3_ds` 让工作流体积翻倍 | 512KB 上限 + 超限跳过 + warn |
| 自动恢复复活用户故意清空的内容 | 只对快照自动；manifest 一律走横幅 |
| `_uiGen++` 误杀正常写回 | 只在 `oldNode` 存在时自增，且先 `flushPendingEdits` |
| 多节点绑定改变写入对象 | 单节点时行为完全等价（`_activeNodeId` 为空即回落） |
| 与另一条对话的改动冲突 | 本文只碰 `loadGraphData` 包装、`flushPrompts` / `schedulePromptFlush` / 迁移三函数 / `getDs` 兜底 / `loadDefaultWorkflow` / `onSerialize`；**refvideo、性能设置、段卡布局不在范围内** |

回滚粒度：P0-1/P0-2 可单独回退（只是少一次落盘）；P0-3/P0-4 回退即回到现状；
P1-1 的 `properties` 键对旧版本无影响（旧版忽略未知 properties）。

## 8. 明确不做

- 不改「分段提示词存在控件里」这个架构（换存储＝重写 `parse_state` + frozen 测试，收益不匹配）；
- 不新增控件 / 不改 `widgets_values` 数量与顺序；
- 不把提示词写 localStorage（体积 + 隐私 + 与项目目录天然不一致）；
