# 导演台三库 / 提示词前端重构计划（基于成熟方案）

日期：2026-09-11　分支：`experimental-branch-2`　工作区：本仓库当前未提交状态

> 本文是对另一 AI 所写导演台三库前端的重构提案。**核心原则：能抄就抄，不自己创新。**
> 只对「成熟方案覆盖不到的、本插件独有的长链续拍环节」才自研。

---

## 0. 先给结论（说人话版）

你的不满不是零散 bug，是**架构选错**：

1. **你在自己造轮子。** 资产库、提示词扩写、剪辑，ComfyUI 社区早就有成熟插件。你想让"资产库管理"和"提示词优化"成熟，最省力的做法**不是修现在这个前端，而是外挂在成熟插件上，只保留本插件独有的引用/打标逻辑**。
2. **前端全塞一个文件（432KB `h3_director.js`）。** 三库、段卡、提示词 v2 表单、transcode 子面板全挤在一起，CSS 互相打架 → 这就是"展开后功能看不到"的直接原因（具体见 §2.1）。
3. **提示词有两套模型并存**（旧三字段 + 新 `prompt_v2` 具象化），还要用户手动"启用/同步/清除" → 这是"具象化抽象"的根源。
4. **「AI扩写」根本不是功能，是让你去终端跑命令的提示**（前端只是把 shell 命令复制到剪贴板）→ 这是"AI扩写是什么意思"的根源。

**一句话方案：**
- 资产库 → **外接/借鉴成熟 DAM（Majoor AssetsManager）**，本插件只做"引用与打标"薄层。
- 提示词优化 → **抄 ComfyUI-MiniMax-H3-Prompt-Enhancer 的节点+本地 LLM 端点架构**，后端复用你已有的 `h3_prompt_expander` 契约，把"复制命令"变成"生成→确认卡→回填"。
- 裁剪/分离/转 latent → **退回 ComfyUI 原生节点**，插件只保留"产物回库"。
- 导演台只留**长链续拍独有**的内容，段卡设置按 4 组重排。

### 1.2 你吐槽的每一条，对应的代码位置

#### (a) 资产库「展开了功能选项直接看不到」

```css
/* h3_director.js:3358 */ .h3d-kindcols{display:grid;grid-template-columns:repeat(3,minmax(0,1fr));gap:14px}
/* h3_director.js:3362 */ .h3d-kindcol .h3d-tilegrid{grid-template-columns:repeat(auto-fill,minmax(150px,1fr))}
/* h3_director.js:3365 */ .h3d-tile{display:flex;flex-direction:column;gap:5px;...}
/* h3_director.js:3378 */ .h3d-tsub{grid-column:1/-1}
```

三库面板本身是 `width:min(1560px,100%)`；展开后又被切成 3 栏（图/视/音）；每栏里再 `auto-fill minmax(150px,1fr)` 铺瓦片。**瓦片实际可用宽度只剩面板的 1/3 再除以列数**。瓦片底部的按钮组：

```
引用 / 裁剪 / 分离 / 转latent / ⇩调入项目 / 入库 / 移出     ← 一个瓦片最多 6~7 个按钮
```

`h3-tbtns` 是 `flex-wrap:wrap`（3376 行），按钮被挤到多行、超出瓦片高度；而**行内子面板 `sub` 是作为瓦片同级 grid item 插进 `h3d-tilegrid` 的**（`grids[...].append(tile, sub)`，4266 行），在 150px 的窄列里 `grid-column:1/-1` 也只剩极窄宽度。→ 「展开子面板看不到内容」是**布局必然结果**，不是偶发 bug。

#### (b) 提示词设置「迷之设置」「跟随全局弄那么大」

```js
/* h3_director.js:6343 */ const refFollow = el("button", "h3d-btn", "跟随全局");   // 独立大按钮
/* h3_director.js:6366 */ const seqFollow = el("button", "h3d-btn", "跟随全局");   // 又一个独立大按钮
```

两个 checkbox 的**语义与全局默认相反**（注释原文：`null=跟随全局默认开`，「自动引用上段」「自动按序生成」关掉才等于旧语义），再各挂一个跟主按钮同级的「跟随全局」按钮 → 用户看到 4 个控件表达 2 个状态，还看不懂哪个是"当前生效值"。

#### (c) 「本段 latent 引用也是错乱无比」

```js
/* h3_director.js:6377-6480 */
latent_ref = { on, frames, src, video, audio }   // 桥
+ tail_src = { asset } | { latent }              // 段尾锚（另一个字段）
```

同一件事（"本段头部接什么桥、段尾钉什么锚"）被拆成：
- `latent_ref.on`（注入上段 latent 桥）
- `latent_ref.frames`（注入帧数，留空=跟随全局）
- `latent_ref.src`（桥来源：上段尾 or latent 库文件）
- `latent_ref.video` / `latent_ref.audio`（keyframe 双分支）
- `seg.tail_src`（段尾锚，与前四个并列在**另一个折叠框**里）

→ 语义重叠（`latent_ref.src` 与 `tail_src.latent` 都能当桥源），用户不可能理清。这就是"错乱"。

#### (d) 具象化 / AI扩写 / 中文意图 / 启用具象化

| 你看到的 | 实际是什么 | 位置 |
|---|---|---|
| 具象化 | 一套新的 `prompt_v2` 结构（画面/镜头/声音/参考/高级分组），与旧的「场景/角色/环境音/配乐/主提示词」**并存双写** | 5322-6100 行 |
| 「启用具象化（从旧字段迁移）」 | 一个**手动开关**：在 `prompt_v2` 与旧字段之间切换。但后端已能按引用自动判定模式（`detectMode`）→ 这个按钮是**架构冗余**，你问得对 | 5916 行 |
| 「中文意图 intent_zh」 | 一个普通 textarea，注释写「给扩写或人工看的中文描述，不进入最终英文」。UI 上没有任何说明它是给谁用的 | 5451 行 |
| 「［AI扩写］复制命令」 | **把一段 shell 命令复制到剪贴板**，让你自己开终端跑 `python tools/h3_prompt_expander/...`，再把结果贴回来 | 5474-5489 行 |

→ 这不是"AI扩写功能"，是"把 CLI 工具的使用说明抄给你"。**功能本身（`tools/h3_prompt_expander/`）已经写好了，只是没集成进前端。**

#### (e) 裁剪 / 分离 / 转 latent 内联一堆 bug

这三个在 ComfyUI 原生就是 `trim` / `split` / `VAEEncode(LoadVideo→VAE)` 能干的。本插件的做法是：

- 行内子面板 `openTrimSub`（4609 行）/ `openTranscodeSub`（4742 行）挂在**被挤压的瓦片网格里**（见 (a)）
- 转码写进 `ds.transcode_jobs`，然后由**主节点「短路专跑」**（`_execute_transcode_only`）执行
- 转码期间用 `mark/unmark/is_busy` 加生成互斥锁，遇忙返回 **423**，前端整排按钮置灰
- VAE 配对靠**扫画布上的 VAELoader** 或服务端扫 `models/vae`（`transcodeVaeFiles`，4661 行）

→ 四条脆弱耦合叠在一起：布局挤压 + 走主节点队列 + 全局 busy 锁 + VAE 猜配对。任何一条出问题，用户看到的就是"内联节点一堆 bug"。

### 1.3 已有的成熟资产：不该重造的部分

**`tools/h3_prompt_expander/` 已经是相当完整的方案**（我之前没注意到它的分量）：

```
normalize.py       规则层预处理（对白/引号/抽象词/高危模式），零成本、不花钱
prompts/system_intent.md    理解跳 → 意图 IR（logline + 不变量 + beats + 逐字 dialogue + risks + clarify）
confirm_card.py    强制确认卡（用户点头前不许编译）
prompts/system_compile.md   编译跳 → H3 英文三字段
validate.py        确定性校验（无 LLM，含 Ref2VA 六段式），repair 最多 2 次
references/h3-dialect.md + scene-packs.md + intent-schema.json

```

这跟外部成熟方案 `ComfyUI-MiniMax-H3-Prompt-Enhancer` 的流水线**几乎一一对应**（它也有：方向输入描述输出 / 严格校验门 / 自修复循环 / 确认环）。**你的工具不缺能力，缺的是"接进前端"**。

同样，`docs/ref_rework/DIRECTOR_DESK_REWORK_PLAN.zh-CN.md`（86.9KB）已经写过一版重构计划，含 F01–F30 缺陷清单、`docs/ref_rework/ACCEPTANCE.zh-CN.md` U01–X03 验收清单。**本计划与它对齐，不另起一套。**

### 2.2 提示词优化：ComfyUI-MiniMax-H3-Prompt-Enhancer

`hyukudan/ComfyUI-MiniMax-H3-Prompt-Enhancer`（GPL-3.0）——**这是你该抄的架构**：

| 它做的事 | 细节 | 你现在的差距 |
|---|---|---|
| 接**本地 LLM** | OpenAI 兼容端点（LM Studio `127.0.0.1:1234/v1`、Ollama `11434/v1`）或**自带 llama-server 跑本地 GGUF**（隔离进程、用完 100% 释放 VRAM） | 你现在只有"复制 shell 命令"，用 `ZHIPU_API_KEY` 云端 key |
| 核心契约 | **"DIRECTION IN, DESCRIPTION OUT"**：H3 没有设置项，提示词只描述"摄像机所见与麦克风所听"，舞台指令不能混进场景内容 | 你的 `h3-dialect.md` 有类似约束 ✓ |
| 结构 | 3 块（T2VA/I2VA/FL2VA/L2VA）/ 6 块（Ref2VA），字段顺序固定 | 你的 `prompts.py` compose_base/compose_reference 已实现 ✓ |
| 对话保真 | `<d>[Language] ...</d>` **100% 逐字**，17 语言 + 88 方言别名 | 你的 README 写明"对白自动转换 `<d>[中文]…</d>`" ✓ 但没做方言 |
| 校验 + 自修复 | **Strict Syntactic Validation Gate** + 自动 LLM repair loop | 你的 `validate.py` + repair 最多 2 次 ✓ |
| **Prompt Studio** | 8 区（Shots/Staging/Subjects/Environments/Media/Camera/Look/Review），抽屉式（720/820/920px），**即时保存进工作流数据，无独立 Save 按钮** | 你的"具象化分组"方向对，但用 `details` 折叠 + 双模型，做成了"迷宫" |
| 输出 | 直接给 `width/height`（16px 对齐）、`duration_seconds`、`aspect_ratio` | 你有 grid.py 的网格数学 ✓ |

**结论：把你的 `h3_prompt_expander` 从"CLI + 复制命令"升级成"前端内联的面板 + 本地 LLM 端点"，架构照着 Prompt-Enhancer 抄。**

这直接回答你的三个疑问：
- **「AI扩写是什么意思」** → 它本该是「把中文意图送 LLM → 出英文 H3 提示词 → 给你看 → 你确认 → 回填」，不是复制命令。
- **「中文意图是什么意思」** → 它就是「AI扩写」的**输入**。两者应该是同一个面板的上下两格（输入意图 → 输出英文），而不是一个 textarea + 一个复制按钮。
- **「启用具象化按钮留着干嘛」** → 该删。既然已有 prompt 模型自动判定模式，就不需要用户手动"启用/清除具象化"。

### 2.3 剪辑/时间线：seesee75-commits/ComfyUI-MiniMaxH3-Director（LTX Director 移植）

- 轨道模型：**Main（图片→首尾关键帧 / 提示词区→带时间戳 `[Shot N]`）+ Reference video 轨 + Audio 轨 + Subject slots（`@ref1..@ref9`）**
- 每段独立提示词区 + **COMPILED PROMPT 实时预览**（采样前就能读到模型将收到的确切文本）
- Subject slot 带 `kind`（人物/环境/道具/风格）+ `retention` 标记（`fully_preserved`…`weak_reference`）+ `called`（后续称呼）
- 关键设计说明：**LTX 的 Prompt Relay mask 无法移植到 H3**（H3 的 DiT 是全自注意力、`mask=None` 硬编码），所以用 storyboard 提示词记法——那是**官方训练记法**，不是权宜之计
- 已知边界：**超 15 秒未解决**（Director Chain 节点已撤回），4–15s 是训练范围

**与本插件的关系：互补，不是竞争。**

| | MiniMax H3 Director | 本插件 SequenceForge |
|---|---|---|
| 作用域 | **单段内**多镜头编排（≤15s） | **多段长链**续拍（超单段上限） |
| 锚定 | 轨道上的图片 = 首尾帧/参考 | 上段尾 latent 直切 + 桥 + 接缝精修 + 二采 |
| 唯一性 | 段内 storyboard | **段间无缝续接**（这是本插件的护城河） |

→ **剪辑器不要自研**。你抱怨的"裁剪/分离/转 latent"只需原生节点；真要时间线，抄它的轨道模型。

### 3.2 分批实施（每批可独立验收）

#### 批次 F：段卡设置页重排（修「看不懂」）

段卡设置页（现 `paneSet`）按 4 组重排，每组标题 + 右侧「当前生效值」小字：

```
▸ 续接
    头部桥：[开关] 接上段尾 / 指定文件 / 不接     ← 原 latent_ref + auto_ref 合并
    段尾锚：[选择] 无 / 图片资产 / latent 文件    ← 原 tail_src
    独立镜头（与上段硬切）[开关]                  ← 原 unlink（保留）
▸ 生成
    参与生成（不上链）[开关]                      ← 原 auto_seq/disabled
    时长（秒）[数字]
▸ 提示词
    （指向中栏，不在设置页重复）
▸ 高级（默认折叠）
    重摇标记 / 二采重置 / 引用调试
```

### 3.3 明确不做的（避免又一轮过度设计）

- ❌ **不引入前端框架**（Vue/React/构建步骤）。官方扩展点够用，抄来的架构也是 vanilla。
- ❌ **不自研通用 DAM / 时间线剪辑器**。用现成插件或原生节点。
- ❌ **不动后端生成核心**（`nodes.py` 主循环、接缝、二采、checkpoint）——那是本插件的护城河，且已验证。
- ❌ **不追求"一个前端搞定所有"**。承认边界：单段 storyboard 编排交给 H3 Director，本插件专注长链。

## 5. 建议的落地顺序与理由

```
A（拆文件+修布局） → 必须先做，否则后面所有改动都在 432KB 里打架
    ↓
E（latent 语义归位）+ F（设置页重排） → 纯前端，风险低，直接解决"看不懂/错乱"
    ↓
D（提示词统一 + 内联扩写） → 解决"具象化/中文意图/AI扩写"三连问
    ↓
B（资产库薄层化） → 需要 B1 定稿后再决定是否引入 DAM
    ↓
C（裁剪/分离/转latent 回退原生） → 最后做，因为它动了后端耦合，风险最高
```

**为什么 A 必须最先做：** 现在 432KB 单文件 + `kindcols` 三栏嵌套布局 = 任何小改都可能触发新的 CSS 冲突。不拆文件，后面全部白干。

**为什么 C 最后做：** 它涉及删除 `transcode_jobs` 后端字段和主节点短路分支，需要回归测试；而用户对它的痛感（"一堆 bug"）在 A2 修好布局后已经大幅缓解。

## 6. 需要你拍板的三个点

1. **资产库走哪条路？**
   - (a) **薄层自绘**：导演台只留引用/打标，通用浏览仍用本插件的 `/h3chain/library_*`（工作量小，但仍是自研）
   - (b) **声明兼容 Majoor AssetsManager**：装了它就用它浏览，本插件只做引用（最省力，但依赖第三方插件）
   - (c) **抄 AssetsPlus 架构自建侧边栏 tab**（中等工作量，自主可控）
   - 我推荐 **(b) 优先 + (a) 兜底**：社区有成熟的就用，没有就薄层。

2. **本地 LLM 后端接哪个？** 抄 Prompt-Enhancer 的话，默认给你一个
   - LM Studio（`127.0.0.1:1234/v1`）—— 最省事，图形界面
   - Ollama（`11434/v1`）—— 命令行
   - llama-server + GGUF（它自带管理，用完释放 VRAM）—— 最省显存
   - 还是继续用你现在 `h3_prompt_expander` 的智谱 GLM 云 key？

3. **调色板问题**：现在导演台是**深色**（`--h3d-ink` 等），而你当前 IDE 是浅色主题。要保留深色（对视频工作友好）还是改成跟随 ComfyUI 主题变量？
