# 总提示词框多段改造（2026-09-14 落地）

把「📋 总提示词」从**粘贴-解析分配**的小工具，改造成**全屏的多段工作台**：
`① 中文意图 → ② 剧本（AI 扩写）→ ③ 结果（AI 提示词优化）`，一次覆盖整条链。
**无首尾帧上传入口**（那是段级运行参数，不属于总框）。

形态上它**不是**「总框里再嵌一排分段提示词框」，而是：

> 顶部一行（全片意图 + 每段时长范围 + 段数 + 模式 + 风格 + 两个 AI 按钮）
> + 中间一个撑满剩余高度的**大文本框**（分段文本直接写在里面）
> + 底部一行（从当前链载入 / 清空 / 取消 / **解析并分配**）

---

## 〇、形态修正：不要在总框里嵌段卡

用户原话：「分段直接写在结果框里面，让结果框进行分配不就行了……这从文本粘贴又是啥意思，
复制文本又是什么鬼……单段扩写压根没必要存在……把总提示词框弄成全屏吧，现在这样三个框，
输入位置太少了。我要的是多段的意图、剧本、结果的流程，而不是在总提示词框里面再嵌入
分段提示词框。」

因此第一版（段卡列表版）**整体推翻**，改为：

| 第一版（已废弃） | 现在 |
|---|---|
| 段卡列表，每段三个折叠框 | **一个大文本框**，段落就是文本里的 `【段N】` |
| 从文本粘贴 / 复制为文本 两个按钮 | 删掉——正文本身就是文本，选中复制即可 |
| 段卡里的「单段扩写」 | 删掉——写单段的地方早就在段级主提示词框 |
| 760px 宽对话框 + 三框分栏 | **全屏**（100vw × 100vh，正文 flex 撑满） |

「意图 / 剧本 / 结果」三段式**保留**，但它是**文本内部的标签**（`意图：` / `剧本：` /
`提示词：`），不是三个 UI 框。解析即分配：`parseMasterPrompt` 读正文，
点「解析并分配」才 `applyMasterPrompt` 写回节点。

## 一、本轮最重要的修正：扩写与优化的分工反了

用户指出：「扩写是把短意图改造成一大段完整剧本，关键不是格式而是剧本；
提示词优化的重点才是格式。」

排查结论：**原实现正是反的**，而且是被提示词明令焊死的——

* `prompts/system_compile.md` 首句：「你不许重新理解用户、**不许加戏**，
  只许把 IR 翻译成 H3 能执行的格式」
* `prompts/system_intent.md`：「不许发明新人物/新道具/新结局」

所以旧的「AI 扩写」实际是 **一句话 → 一段 4–15s 官方提示词的编译器**，
出不了剧本（`service.expand_via_config` 只吃一个 `duration`，
被 `max(4, min(15, d))` 钳死）。

**新分工**：

| | 职责 | 产物 | 格式 |
|---|---|---|---|
| AI 扩写 | 内容发散 | 一大段中文剧本，填满目标时长 | 自由格式，**不套 H3 字段** |
| AI 提示词优化 | 格式编译 + 密度压缩 | 官方三/六字段，进模型 | 严格 H3 官方 |

时长从**定值**改成**范围**（如 8–12 秒），模型在范围内自定每段秒数。

## 二、后端实测结论（事实基础）

### 1. AI 扩写能扩写出完整剧本吗？——原来不能，设计上就是单段

见上。`duration` 钳在 4–15s，intent IR 的 beats 是**段内节拍**，
`render_h3()` 只渲染单段。想要多段剧本必须新增 Outline 层（本轮已加）。

### 2. AI 真能理解参考图吗？——能传，但三个条件卡着

链路已通：`collectSegMedia`（首尾帧锚 + 段参考图 ≤8 张 → dataURL，
编号 `<Picture N>`）→ `/h3chain/expand*` → `optimizer._api_generate` 的 `image_url`。
但是：

* **必须是视觉模型**。默认 `glm-4-flash` 不是；非视觉模型 → 图被静默丢弃，**不报错**。
* **只传图片**。optimizer.py 注释写明「视频/音频只传 label」→ 参考视频/音频 AI 看不见。
* **扩写侧「哪张图是谁」的说明走 `style_note`**，而双跳第二跳把它丢了（见下）。

### 3. AI 提示词优化真能严格按 H3 官方格式吗？——中文模式下会跑偏（已修）

`build_system_prompt` 写对了（Ref2VA 六段 / FL2VA 三节+裸词 `picture 1`/`picture 2`
/ 其它三节），但 `pick_rule_text` 在 `lang=中文` 时注入
`minimaxh3_custom_ref2v_prompt_writing_zh.txt` —— 一份**全参考四字段**规则
（`summary`/`detailed_description` + `<@名字>`/`<#名字:对话>`），
且注入语写着「此规则优先于其他通用格式要求」。

→ 给 T2VA/FL2VA 段优化时，模型同时收到两条互相矛盾的「最高优先级」指令，
产出的 `<@小李>` 这类非官方标记还会经 `applyAiToV2` 原样写进 `pv.shots[0].description`
进模型。另外优化结果**从不校验**（扩写有 validate+repair，优化没有）。

### 4. 顺带查到的两个真 bug

* **双跳第二跳丢上下文**（h3_expand.py）：第二跳只发 `"意图 IR：\n" + json`，
  把 duration、style_note（随图说明）、预处理 notes、场景包全丢。
  而前端 `two_step: true` 是**写死**的 → 实际一直走信息更少那条路。
* **风格三档 temperature 从未下发**：`chat()` → `generate_json` → `_api_generate`
  里写死 0.2。STYLES 的 0.2/0.3/0.6 只在提示词加一句话，采样温度恒定。

## 三、分段格式（完善版，唯一交换格式）

即全屏工作台**正文里的内容本身**——段就是文本里的 `【段N】`，不是 UI 上的卡片。
可直接从聊天界面/外部 AI 整段复制进来，也可整段复制出去续改。

```
【段1】
时长：9
独立镜头：否
参考：角色1，图片2
意图：雨夜霓虹市场，女孩回头笑说跟上我
剧本：
时长：9 秒

镜头一（0–3 秒）：……
镜头二（3–9 秒）：……

台词：女孩：「跟上我。」
环境声：雨声、摊贩叫卖
背景音乐：无

提示词：
integrated_multimodal_description: [Shot 1] 实拍、电影感……

overall_soundscape: 雨声持续。

non_diegetic_music: N/A

【完】
```

* 新增 `意图`→`intent`、`剧本`→`script`；`提示词`→`main`（进模型）保持原义。
* 旧标签 `场景/角色/环境音/配乐` **仍解析**（落旧字段），**导出不再写**。
* **正文块保护**（本轮修的真 bug）：一旦进入 意图/剧本/提示词/旧四框 任一正文块，
  段级标签（时长/独立镜头/参考）在正文里**不再生效**，原样归入正文。
  否则剧本里模型写的「时长：9 秒」「配乐：无」会把 `seg.seconds` 冲成 NaN、
  剧本内容被截断（`MP_BODY_KEYS`）。
* 剧本模板里的「台词 / 环境声 / 背景音乐」是**刻意避开**「对白 / 环境音 / 配乐」的
  ——后三个是段级标签名，写在行首会被当标签。
