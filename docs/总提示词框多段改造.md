# 总提示词框多段改造（2026-09-14 落地）

把「📋 总提示词」从**粘贴-解析分配**的小工具，改造成**全屏的多段工作台**：
`① 中文意图 → ② 剧本（AI 扩写）→ ③ 结果（AI 提示词优化）`，一次覆盖整条链。
**无首尾帧上传入口**（那是段级运行参数，不属于总框）。

形态上它**不是**「总框里再嵌一排分段提示词框」，而是：

> 顶部一行（全片意图 + 每段时长范围 + 段数 + 模式 + 风格 + 两个 AI 按钮）
> + 中间一个撑满剩余高度的**大文本框**（分段文本直接写在里面）
> + 底部一行（从当前链载入 / 清空 / 取消 / **解析并分配**）

---

## 〇、形态修正：不要在总框里嵌段卡

用户原话：「分段直接写在结果框里面，让结果框进行分配不就行了……这从文本粘贴又是啥意思，
复制文本又是什么鬼……单段扩写压根没必要存在……把总提示词框弄成全屏吧，现在这样三个框，
输入位置太少了。我要的是多段的意图、剧本、结果的流程，而不是在总提示词框里面再嵌入
分段提示词框。」

因此第一版（段卡列表版）**整体推翻**，改为：

| 第一版（已废弃） | 现在 |
|---|---|
| 段卡列表，每段三个折叠框 | **一个大文本框**，段落就是文本里的 `【段N】` |
| 从文本粘贴 / 复制为文本 两个按钮 | 删掉——正文本身就是文本，选中复制即可 |
| 段卡里的「单段扩写」 | 删掉——写单段的地方早就在段级主提示词框 |
| 760px 宽对话框 + 三框分栏 | **全屏**（100vw × 100vh，正文 flex 撑满） |

「意图 / 剧本 / 结果」三段式**保留**，但它是**文本内部的标签**（`意图：` / `剧本：` /
`提示词：`），不是三个 UI 框。解析即分配：`parseMasterPrompt` 读正文，
点「解析并分配」才 `applyMasterPrompt` 写回节点。

## 一、本轮最重要的修正：扩写与优化的分工反了

用户指出：「扩写是把短意图改造成一大段完整剧本，关键不是格式而是剧本；
提示词优化的重点才是格式。」

排查结论：**原实现正是反的**，而且是被提示词明令焊死的——

* `prompts/system_compile.md` 首句：「你不许重新理解用户、**不许加戏**，
  只许把 IR 翻译成 H3 能执行的格式」
* `prompts/system_intent.md`：「不许发明新人物/新道具/新结局」

所以旧的「AI 扩写」实际是 **一句话 → 一段 4–15s 官方提示词的编译器**，
出不了剧本（`service.expand_via_config` 只吃一个 `duration`，
被 `max(4, min(15, d))` 钳死）。

**新分工**：

| | 职责 | 产物 | 格式 |
|---|---|---|---|
| AI 扩写 | 内容发散 | 一大段中文剧本，填满目标时长 | 自由格式，**不套 H3 字段** |
| AI 提示词优化 | 格式编译 + 密度压缩 | 官方三/六字段，进模型 | 严格 H3 官方 |

时长从**定值**改成**范围**（如 8–12 秒），模型在范围内自定每段秒数。

## 二、后端实测结论（事实基础）

### 1. AI 扩写能扩写出完整剧本吗？——原来不能，设计上就是单段

见上。`duration` 钳在 4–15s，intent IR 的 beats 是**段内节拍**，
`render_h3()` 只渲染单段。想要多段剧本必须新增 Outline 层（本轮已加）。

### 2. AI 真能理解参考图吗？——能传，但三个条件卡着

链路已通：`collectSegMedia`（首尾帧锚 + 段参考图 ≤8 张 → dataURL，
编号 `<Picture N>`）→ `/h3chain/expand*` → `optimizer._api_generate` 的 `image_url`。
但是：

* **必须是视觉模型**。默认 `glm-4-flash` 不是；非视觉模型 → 图被静默丢弃，**不报错**。
* **只传图片**。optimizer.py 注释写明「视频/音频只传 label」→ 参考视频/音频 AI 看不见。
* **扩写侧「哪张图是谁」的说明走 `style_note`**，而双跳第二跳把它丢了（见下）。

### 3. AI 提示词优化真能严格按 H3 官方格式吗？——中文模式下会跑偏（已修）

`build_system_prompt` 写对了（Ref2VA 六段 / FL2VA 三节+裸词 `picture 1`/`picture 2`
/ 其它三节），但 `pick_rule_text` 在 `lang=中文` 时注入
`minimaxh3_custom_ref2v_prompt_writing_zh.txt` —— 一份**全参考四字段**规则
（`summary`/`detailed_description` + `<@名字>`/`<#名字:对话>`），
且注入语写着「此规则优先于其他通用格式要求」。

→ 给 T2VA/FL2VA 段优化时，模型同时收到两条互相矛盾的「最高优先级」指令，
产出的 `<@小李>` 这类非官方标记还会经 `applyAiToV2` 原样写进 `pv.shots[0].description`
进模型。另外优化结果**从不校验**（扩写有 validate+repair，优化没有）。

### 4. 顺带查到的两个真 bug

* **双跳第二跳丢上下文**（h3_expand.py）：第二跳只发 `"意图 IR：\n" + json`，
  把 duration、style_note（随图说明）、预处理 notes、场景包全丢。
  而前端 `two_step: true` 是**写死**的 → 实际一直走信息更少那条路。
* **风格三档 temperature 从未下发**：`chat()` → `generate_json` → `_api_generate`
  里写死 0.2。STYLES 的 0.2/0.3/0.6 只在提示词加一句话，采样温度恒定。

## 三、分段格式（完善版，唯一交换格式）

即全屏工作台**正文里的内容本身**——段就是文本里的 `【段N】`，不是 UI 上的卡片。
可直接从聊天界面/外部 AI 整段复制进来，也可整段复制出去续改。

```
【段1】
时长：9
独立镜头：否
参考：角色1，图片2
意图：雨夜霓虹市场，女孩回头笑说跟上我
剧本：
时长：9 秒

镜头一（0–3 秒）：……
镜头二（3–9 秒）：……

台词：女孩：「跟上我。」
环境声：雨声、摊贩叫卖
背景音乐：无

提示词：
integrated_multimodal_description: [Shot 1] 实拍、电影感……

overall_soundscape: 雨声持续。

non_diegetic_music: N/A

【完】
```

* 新增 `意图`→`intent`、`剧本`→`script`；`提示词`→`main`（进模型）保持原义。
* 旧标签 `场景/角色/环境音/配乐` **仍解析**（落旧字段），**导出不再写**。
* **正文块保护**（本轮修的真 bug）：一旦进入 意图/剧本/提示词/旧四框 任一正文块，
  段级标签（时长/独立镜头/参考）在正文里**不再生效**，原样归入正文。
  否则剧本里模型写的「时长：9 秒」「配乐：无」会把 `seg.seconds` 冲成 NaN、
  剧本内容被截断（`MP_BODY_KEYS`）。
* 剧本模板里的「台词 / 环境声 / 背景音乐」是**刻意避开**「对白 / 环境音 / 配乐」的
  ——后三个是段级标签名，写在行首会被当标签。

## 六、三框化改版（2026-09-15）

用户反馈四条，逐条落地：

1. **总框没有资产引用栏** → AI 扩写/优化拿不到任何参考素材。
2. **意图栏只有一行高（38px）**，写不了一段话。
3. **缺一个独立的结果浏览框**：三层混在一个大文本框里，改一层要在长正文里翻找。
4. **模式选择看着像摆设**，且范例太草（官方字段被 `……` 截断）。

### 形态

```
顶行：每段时长范围 / 段数 / 模式 / 风格 / [✨AI 多段扩写] [✨AI 多段提示词优化] [⚙]
      ↳ 模式右侧实时说明它改了什么格式
引用栏：参考素材（AI 可见）—— 图片素材 chip 勾选 + 全选/清空/⟳
① 意图   20% 高（最小，一段话）· 可拖右下角伸缩
② 剧本   30% 高（中文自由格式）
③ 结果   46% 高（最大，H3 官方格式，唯一进模型）
底行：从当前链载入 / 清空 / 取消 / 解析并分配
```

三个框各装自己那一层，**段头 `【段N】` 在三框里同序对应**；提交时
`mpComposeBoxes` 合成一份标准分段文本再交给 `parseMasterPrompt`——
文本格式与旧版、与外部 AI 续改**完全兼容**（有测试锁死：三框合成 ≡ 旧版导出）。

### 关键实现点

| 点 | 说明 |
|---|---|
| `mpSplitBox` / `mpComposeBoxes` | 三框 ⇄ 分段文本；框内无段头 = 单段；整框空 = 不动该字段；段头空正文 = 显式清空 |
| `collectMasterMedia` | 勾选的图 → `data:image` + `<Picture N>` 角色说明；后端 `optimizer._media_images` 只吃图片，故只收 image（上限 8） |
| expandMulti / optimizeMulti | **补传 `media` + `style_note`**：后端 `service.screenplay_via_config` 与 `optimize_multi_once` 早支持，前端以前没传，等于 AI 一直闭着眼扩写 |
| 模式 | 下拉不再静默：`MP_MODE_HINT` 实时显示它改变哪一档格式，并**同步切换 ③ 的占位骨架**（base 三字段 / I2VA·FL2VA·L2VA 前置官方关键帧对齐整句 / Ref2VA 六段式） |
| 防护 | ③ 整框为空却点分配 = 会清空全链提示词，先 `confirm` 拦一道 |

### 模式确实改变格式（核对结论）

`optimizer.optimize_once` 拿 `task` 做两件事：`build_system_prompt` 按 task 分支
（Ref2VA 六节 + `<Subject N>`/`<Picture N>`；FL2VA 小写裸词 picture 1/2；其余三节），
`pick_rule_text` 按 task 切规则文件（base ↔ Ref2VA 两套，见 `optimizer.REF_TASKS`）。
所以模式不是摆设——只是以前界面上没说，也没让它体现在范例里。

### 顺手修掉的真 bug

`parseMasterPrompt` 的 `pushBody` 只在「记过空行」时才补换行，于是**连续两行正文被直接
拼成一行**（多行剧本、`integrated_multimodal_description` 里的逐行 `[Shot N]` 一进一出
就糊掉）。旧测试只断言 `indexOf("镜头二") > 0`，没查出这条。现改为：已有内容至少补
一个 `\n`，中间空 N 行补 N+1 个，首行（含标签后无内容的空串）不加前缀。

### 测试

`tests/js/master_prompt_three_boxes_check.js`（新增，30 例）：三框合成与回环、段数取三框
最大、缺段头归入段 1 并告警、整框空不动字段、段头空正文显式清空、合成 ≡ 旧版导出、
连续行不拼接、端到端往返。旧 `master_prompt_segments_check.js` 26 例全过。

## 七、对齐指令与首尾帧上传的四个洞（2026-09-15）

用户问「对齐指令到底是怎么个流程、会不会被优化覆盖」——顺着这条线查出四个真问题。

### 1. AI 提示词优化会把对齐指令冲掉（确实是）

优化器只产出官方三/六字段，**不含**关键帧对齐指令（那是由 `resyncAlignmentLines`
按本段首尾帧锚现算的编译产物）。`runOptForSegment` 拿到结果整段写回 ③，
"Picture 1 aligns with the 0.00-second mark…" 就没了 —— 模型于是失去首尾帧锚。
`applyMasterPrompt`（总提示词「解析并分配」）同理。

修：写回后立刻 `resyncAlignmentLines(node, idx)` 补回；原稿/优化稿切换存的是补回后的
最终文本（`_optAfter`），否则切一次"优化稿"又丢一次。

### 2. "对齐指令输不进去 / 一改就没了"

`resyncAlignmentLines` 只写 `ds.prompts`（widget），**没碰屏幕上的富文本编辑器**。
编辑器里还是旧文本，用户一动键盘 blur 就把旧文本回写，补的对齐行立刻消失。
刷新补不了：焦点在框里时整卡重建被焦点守卫挡掉，所以"切屏才看得见"。

修：新增 `_promptEditors` 登记表（③ 结果框建好时 `registerPromptEditor`），
程序改提示词后 `syncPromptEditor` 直接改 DOM（保留焦点与光标），再排一次轻量重绘。

### 3. 首尾帧渠道上传会把上一张"覆盖掉"

后端不覆盖（同名落 `x_2.png`、重名标签加序号，已用真实接口验证过连传两张都在）。
真因在前端：`persistPool` 拿 `ds.ref_assets` **整表**写回 `manifest["assets"]`，
而首尾帧上传**只落盘、不进节点池**，于是在池子被 hydrate 刷新前的任何一次写清单
都会按旧池覆盖 —— 刚传的（和更早传的）就从项目库里没了。

修：新增 `pushPoolAsset`，上传成功后立刻补进 `ds.ref_assets`；再 `hydratePool(true)`
强制按最新 manifest 重建池 + `scheduleRefresh(120)`（不等"切屏"）。

### 4. 首尾帧选图不显示其它渠道上传的图

候选图只取 `ds.ref_assets`（widget 缓存），素材库/其它入口上传的图要等一次刷新才进得来。
修：选图弹窗改为 async，候选图 = 项目库（`manifest.assets + asset_links`，与
`hydratePool` 同口径）∪ 节点池。

顺带修了 `getDs` / `setDs`：两处都按 `a.file` 一刀切过滤 `ref_assets`，
把"只有 asset_id、file 由后端回填"的全局库链接条目整批抹掉（poolFromManifest 早就
专门处理过，但读写两端没跟上）。改成 `a.file || a.asset_id`。

# 后续（2026-09-19）：退回**纯分段流水线**

上面这版（全屏多段工作台 + 三个 AI 入口）被推翻。用户原话要点：

> 「资产引用语义怎么能跟分段提示词框是不同的呢……总提示词框干嘛要跟分段提示词框的
> 提示词同步……它不应该是一个结果框，它应该纯粹是个分配框……AI 分段提示词优化也有点
> 多余了，干脆整个移除掉……退化回纯粹的分段流水线，类似于 main 分支那种。」

## 改了什么

| 项 | 之前 | 现在 |
| --- | --- | --- |
| 定位 | 结果框 / AI 工作台 | **纯分配框**（粘进来 → 解析并分配） |
| 打开时 | 自动载入链上提示词（= 与段卡同步） | **空框**；「从当前链载入」是手动按钮 |
| AI | 「✨ AI分段提示词优化」+ ↩ 原稿 + 模式 + 缺省时长 + 参考图勾选 + ⚙ 设置 | **全撤**（格式清洗在段卡：扩写+优化 / 提示词优化） |
| 段级标签 | 时长 / 独立镜头 / **参考** / 提示词 | 时长 / 独立镜头 / 提示词 |
| 资产引用 | `参考：标签` 直接写 `seg.refs`（第二通道） | **只认正文里的 `@素材名`**，分配时 `syncRefsFromText` 派生 `seg.refs`（与段卡逐字同一函数） |
| 旧标签 | 场景/角色/环境音/配乐 解析后写回旧字段 | 与 意图/剧本 一样**只读丢弃 + notes 点名**（不进正文、不写字段） |

## 为什么「参考：」必须整条删掉

它是**第二条资产引用通道**：段卡的口径是「正文是唯一真相，`seg.refs` 由正文 `@序列`
派生」，总提示词框却是「另写一份标签清单直接塞 `seg.refs`」。两条通道必然对不上，
这正是"总提示词框引用不对 / 和分段两回事"的来源。现在两边共用 `refsFromText`，
工作台 info 行显示的「素材引用 N 处」就是分配后 `seg.refs` 的长度。

## 为什么旧标签是"丢弃+提示"而不是"当正文"

场景/角色/环境音/配乐/意图/剧本/参考 这些块的内容**不该进模型**。看不懂就并进正文，
等于把"不进模型"的内容悄悄送进模型；静默丢弃，用户又会以为内容还在。所以认出即丢、
并在 notes 里点名（「参考」单独一条，提示改写成正文里的 `@素材名`）。
