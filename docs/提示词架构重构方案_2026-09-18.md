实施中**新发现并修掉**的真 bug（方案里没列）：

1. **段级标签后的裸正文被并进 `refs`**：`参考：角色1` 后面接正文时，`field` 还停在 `refs`，正文被当成参考标签续行（refs 从数组变成一坨字符串）。三框时代每段都以 `提示词：` 开头所以没暴露，单框后当场踩到（`parseMasterPrompt` 里 `field` 归位到 `main`）。
2. **无段头单段文本的空行被丢**：官方三字段靠空行分节，粘一段不带【段1】的文本进来会被压成一行（`stray` 现在保留空行并去首尾空行）。
3. **结构化切换不幂等**：编译产物 `, the camera cuts to ` 每切一次视图就多叠一层，且 `At MM:SS.mmm` 只写 `at` 不写 `start_seconds`，下一轮时间点被均分重算（3 秒的镜第二次变 1 秒）。
4. **`asset_chip_check.js` 静默崩**：`poolFromManifest` 多依赖了 `cleanRefName`/`assignMarks`，抽函数时没一起抽 → ReferenceError。已补，并把 `tests/js/*_check.js` 全收进 pytest（`tests/test_js_checks.py`），以后不会再出现"脚本坏了而全量测试一片绿"。
5. **`_harness.js` 假节点的 type 写错**（`H3SeamlessChain` ≠ 导演台 `NODE_TYPE`），`findNode()` 恒为 null，凡依赖真节点的 jsdom 用例其实一条都没验到。

### 已确认的两个「显示」坑（用户点名的后缀溢出 / 显示不全）

1. **后缀溢出**：别名是 **stem**（`clean_alias` 剥扩展名，`asset_store.py:69-75`）。用户/LLM 写 `@猫.png` 时，分词器按池内最长前缀只匹配到 `猫`，剩余 `.png` 作为普通文本留在正文里 → 绿框后面挂个裸 `.png`。这就是"奇怪的后缀溢出"。
   - 分词器：`h3_director.js:567 refTokens`（前端）/ `nodes.py:577 _find_refs`（后端），同口径。
2. **显示不全**：别名在落库时就被截到 24 字符（`asset_store.py:75`、`ALIAS_MAX=24`）。长文件名被砍，且**两个长文件名前 24 字符相同时会互相顶掉**（前缀匹配先命中谁算谁）→ "引用错了图还看不出来"。

> 这两条是同一根因：**引用用的名字 ≠ 素材的真实名字**。本次重构用"@完整文件名（含后缀）"从根上解决。

### 1.1 新形态


## 2. 资产引用规范化（本次最核心的改动）

### 2.1 三层名字，各管一段

```
素材真实文件  女主.png
   ↓ 入库时自动分配（可手改）
标  注       图片1          ← 给 LLM 看（短、稳、不会写错）
   ↓ 前端/后端双向编译
引用语法      @女主.png     ← 提示词框里写的、落库的
   ↓ 执行期编译
官方 tag      <Picture 1>   ← 真正送进 H3 模型
```

### 2.2 标注（mark）

- 入库（进项目库）时按**类型独立、入库顺序递增**自动分配：`图片1 图片2 … / 视频1 … / 音频1 …`。
  - 存储：`manifest["asset_links"][].mark`（`projects.py:328 link_asset`、`_clean_asset_link:267`）+ `ds.ref_assets[].mark`（`h3_director.js:1543`）。
  - 后端新增 `asset_store.mark_of(kind, seq)`；`_clean_asset_link` 增加 `mark` 白名单清洗。
  - **编号不回收**：删素材后编号留空，新素材继续递增（避免旧提示词里的标注悄悄指向另一张图）。⚠️ 待确认，见 §8-Q1。
- 手动改标注：素材库卡片菜单加「改标注」（复用 `lib_alias` 通道，`routes.py:1386` / `h3_api.js:114`），重名直接拒绝（沿用现有重名拦截）。

### 2.3 引用语法改为「@完整文件名（含后缀）」

- 素材记录新增 **`ref_name`**（= 原始文件名含后缀，如 `女主.png`）。匹配表从 `label`(stem) 换成 `ref_name`。
- 分词器改造：`refTokens`（`:567`）/ `_find_refs`（`nodes.py:577`）匹配表换成 `ref_name`，**仍是池内最长前缀精确匹配**——`猫.png` 会整体命中，`.png` 不再溢出。
- 悬空引用（`@xxx` 池里没有）→ 红框 + title 提示（现成机制，`:535 makeTokenTag` / `:552 h3d-rtok-missing`），**不需要新写**。
- 显示不全：`shortLabel` 改为 **CSS `text-overflow: ellipsis` + `title` 挂全名**，不再靠截断改名（截断是错的根源）。

### 2.4 送 LLM：发标注，收回全名

- 出参：`collectSegMedia`（`h3_director.js:2951`）的 `media[].label` 由「别名」改成「**标注**」（`图片1`）。
- 正文也一起编译：正文里的 `@女主.png` → `@图片1` 再发给 LLM（后端 `optimizer.build_system_prompt` 输出「可用素材：@图片1、@图片2」，`optimizer.py:250`）。
- 回参：LLM 返回后把 `@图片1` 反编译回 `@女主.png`。
  - **统一在后端做**：新增 `asset_store.decode_marks(text, mark_map)`，前端与后端共用同一份实现（前端镜像一份，用单测锁死同口径）。
  - 反编译失败（LLM 造了个 `@图片99`）→ 原样保留为悬空引用红框，不静默丢。

### 2.5 送模型：`@全名` → `<Picture k>`

- 沿用现有执行期链路，只换匹配表：`seg_label_orders`（`nodes.py:1117`）→ `compile_refs`（`asset_store.py:371`）→ `_apply_label_tokens`（`nodes.py:657`）。
- 编号规则**不变**：段内按 kind 各自从 1 编号、同一素材复用编号、图 9/视 3/音 3 硬上限。
- `asset_store` 索引增加 `by_ref_name`（与 `by_alias` 并列），保证 `@全名` 能解析。

### 2.6 引用条简化

- chip：**有引用=绿（`.on`），无引用=灰**，文本只显示素材名，**去掉 `×N`**（`:1017`）。
- counter：去掉「共 M 次」「图x/9·视y/3·音z/3」的常驻计数，只留一句 `已引用 N 个素材`；**超过 9/3/3 时整句变红并点名超限类别**（硬约束要留，只是不常驻显示）。
- `refCount / canAddRef` 的"重复次数软上限 `REF_REPEAT_MAX=9`"（`:1834-1873`）随计数一起删；`seg.refs` 语义从"出现序列"收敛为"**去重集合**"（顺序仍按正文首次出现，用于编号）。
- `syncRefsFromText`（`:1201`）改为产出**去重**序列。

### 6.2 旧档迁移（必做，否则满屏红框）

3. 标注回填：按现有 `asset_links` 顺序补 `mark`（无历史顺序时用当前顺序）。
4. `ref_name` 缺省 = 现有 `file` 的文件名部分（无 `file` 时回落到 `label + 原扩展名`）。

| Q6 | 文件名含空格 / 特殊字符（`my photo.png`）怎么办？ | 入库时自动把空格替换成 `_` 并提示（`@` 分词按空格断句，留空格必炸） |

| Q8 | 删素材后标注编号回收重排吗？ | **不回收**（编号留空、新增继续递增），避免旧提示词里的标注悄悄改指向 |
| Q9 | `ds.optimizer`（含新增的扩写参数）要不要落进 manifest？ | **要**，顺手修——现在换机器/重载就丢（`h3_director.js:1700`） |

## 9. 风险点（列给你审，不是结论）

1. **前后端同口径漂移**：`cleanLabel`（`h3_director.js:370`）与 `clean_alias`（`asset_store.py:58`）是两份实现，历史上漂过。新加 `ref_name` 也要两份——必须靠单测锁死（`tests/js` 现有前端测试可挂）。
2. **执行期未知引用静默放行**：`_apply_label_tokens`（`nodes.py:670`）只对 `[[..]]` 报错，`@unknown` 静默放过。换全名后如果迁移漏了，会静默少图 → 建议把"@ 未知引用"也升级为**生成前校验报错**（现在只在前端标红）。
3. **`ds.optimizer` 不进 manifest**（`h3_director.js:1700`）：换机器/重载配置会丢。本次新增的扩写参数也在此列，是否顺手落盘？建议顺手做。
4. **prompt_v2 前后端已漂移**：后端 `prompts.py:89` 有 `visual` 字段，前端 `h3_prompts.js` 没有。做结构化转换前要先把两份结构对齐，否则 round-trip 不可能幂等。
5. **933 上限与"不计数"的冲突**：不显示计数后，用户可能一口气勾 12 张图才在生成时报错。建议在**点第 10 张图时立刻红字提示**（不等到生成）。
