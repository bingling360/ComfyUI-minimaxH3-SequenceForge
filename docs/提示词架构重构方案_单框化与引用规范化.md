## 0. 一句话

把「意图 → 剧本 → 结果」三段式压成**一个框**；把资产引用从"每个框各挂一条"收成**段卡一条 + 绿/灰状态**；
把 `@素材名` 的引用链路**规范成两层编号**（给 LLM 的稳定"标注" vs 给模型的官方 token）；
总提示词框退回 main 的**单框八标签工具**；具象化从常驻 tab 变成**「结构化提示词」按钮**；
并把现在"输入即重建整卡"造成的溢出 / 显示不全**从根上**改掉。

### 3.3 素材标注（两层编号的关键一层）

**存哪**：项目 manifest 的 `asset_links[]` 条目，新增两个字段
```python
# projects.py:_clean_asset_link (281-287) 扩展
ent = {"asset_id": aid, "alias": alias, "kind": kind,
       "mark": "图片1",        # 标注：项目内唯一，发给 LLM 用它
       "mark_auto": True}      # True=可被自动重排；用户手改后置 False
```

**怎么发号**：入库路径统一走新函数 `assign_mark(links, kind)`（`projects.py`）——
`mark = KIND_CN[kind] + str(该项目同类已有 max 序号 + 1)`，首次写入即在 `asset_link` 落盘。
需要改的入口：`POST /h3chain/asset_link`（`routes.py:540` 区块）、`library_upload:2346`、`import_asset:2338`、`lib_stage:2309`。
**老项目迁移**：读 manifest 时若条目缺 `mark` → 按数组序补发（幂等，只补缺失的）。

**不做自动重排**（编号稳定 > 连续），删素材留空号；另给一个显式「重新编号」按钮。

**手动改**：引用栏 chip 上右键 → 「改标注」；或素材库列表直接编辑。
改的时候必须查重（`mark` 项目内唯一），重名直接拒绝并提示。

**编码/解码层**（纯函数，放 `web/h3_prompts.js`，可单测）：
```js
marksToText(text, pool)  // @阿依.png  → @图片1     （出：给 LLM）
```

### 3.6 状态监控与显示规范（**一开始就规避，不留给后期修**）

**根因 1 —— 输入即重建整卡**（这是"显示不全 / 跳动"的主因）
`cardsSignature:5005` 把 `plan: (plan||[]).map(it => ["p", it.text])` 放进了签名，而 `planFromDs:3438` 里
`plan = ds.prompts.map(t => ({text: t.trim()}))` —— **提示词正文在签名里**。
于是每敲一个字签名就变 → 整卡重建；现在只靠"焦点守卫"（注释 `:5021`）勉强挡着，一旦失焦或别的字段变化就重建
→ 滚动位置跳回顶部、内容看着"不全"、chips 位置跳动。

**改法**：正文**移出签名**，改事件驱动局部刷新：
```
框内 input（已有防抖 fireInput:713）
   → ① 引用栏状态刷新（绿/灰 + chips on 态）
   → ② 编译映射条刷新
   → ③ 段条 pill 的"有内容"点刷新
   → ④ 落盘（flushPrompts 防抖）
   ✗ 不触发 buildCards
```

**根因 2 —— 长 ASCII 串不换行**：`.h3d-rta:4467` 用 `word-break:break-word`，对
`@goodmorning_2024_14_02_12.png` 这类无空格长串**不生效** → 横向溢出。
→ 改 `overflow-wrap:anywhere; word-break:break-word;`（两个都写，兜底 Chromium 差异）。

**根因 3 —— 单个标签可宽过容器**：`.h3d-rtag:4470` 是 `inline-flex` 且**无 `max-width`** → 撑出横向滚动条。
→ 加 `max-width:min(100%,260px)`；标签内文字 `overflow:hidden;text-overflow:ellipsis;white-space:nowrap`；
完整名放 `title`（已经这么做了 `:490`）。

**根因 4 —— 全量重渲染丢滚动位置**：`render()` `:627` 走 `box.replaceChildren()`。
→ 三条闸门：① 值未变直接 return；② `@名` 集合与文本都未变时跳过重建；
③ 真要重建时保存/恢复 `box.scrollTop` 与光标（`caret:642` / `placeCaret:652` 已有）。

**其余显示规范**
- `.h3d-refrow:4564` 是 `flex-wrap:wrap`，chips 多时**无限长高** → 加 `max-height:96px; overflow-y:auto`，
  或 >12 个折叠成 `… +N`。
- 单框高度统一：`min-height:180px; max-height:44vh; overflow:auto`（不用百分比高度）。
- 富文本 disabled 态：`api.disabled` `:831` 只 `contentEditable=false` + `classList.add("h3d-rta-off")`；
  **需确认 `.h3d-rta-off` 是否有样式声明**，没有就补上（否则"只读但看起来可编辑"）。

## 6. 坑点清单（**先看这节再动手**）

**P1 · 两层编号不能混用（最重要）**
给 LLM 的「标注」（图片1 = 项目库第 1 张图，**长期稳定**）和给模型的 `<Picture N>`
（= **本段实际挂载顺序**，每段重算，`asset_store.compile_refs:411-421`）是**两套独立编号**。
绝不能把标注号直接当 token 号用 —— 若某段只引用了"图片3"，它必须编译成 `<Picture 1>`（本段附件只有 1 张）。
所以：**两层分离 + UI 明示映射**（§3.2 编译映射条）。这是全案最容易踩错的地方。

**P2 · 命名空间冲突**：素材 `alias` 若正好叫「图片1」，编码/解码会串。
→ ① 解码时标注优先；② 发号时对 alias 加约束（禁止纯「图片N」/「视频N」/「音频N」形态，`asset_store.clean_alias:58` 加一条校验）。

**P3 · 标注唯一性与漂移**：手动改标注必须查重；删除素材后**不重排**（留空号），否则所有已生成段里的引用语义漂移。

**P4 · 盘上永远存原名**：标注只在 LLM 往返路径上存在。任何"顺手把标注写进 `ds.prompts`"的实现都是 bug ——
一旦落盘，执行期 `_find_refs` 找不到它就会静默丢图。

**P5 · 编辑器会把 `@图片1` 判成悬空引用标红**：`refTokens:602` 对 `@` + 池里没有的名字标红框
（因其依赖 `labelsOf()`）。标注不是 label → 用户手打 `@图片1` 会得到一个红框。
→ 编辑器加一个分支：`@` 后命中 `mark` → 渲染成**黄色"这是标注"提示框** + 一键替换成 `@完整名.png`。
（这既是防混淆，也顺手教用户两层编号的关系。）

**P6 · 测试面必然失效**（改之前先认领）
| 文件 | 原因 |
|---|---|
| `tests/js/master_prompt_three_boxes_check.js` | 三框没了 → **重写** |
| `tests/js/master_prompt_segments_check.js` | 单框格式变更 → 适配 |
| `tests/test_prompt_editor.py` | 断言 `intent_zh`、`buildRefBar` |
| `tests/test_rework_v2.py` | 断言 `intent_zh` |
| `tests/js/frame_anchor_persist_check.js` | 涉 `restoreSegField` / `flushPrompts` |
| `tests/js/alignment_resync_check.js` | 涉 `applyMasterPrompt` |
| `tests/test_expand_multi.py` | 若沿用接口则不动；若改协议要同步 |

**P7 · 本机跑不了全量测试**：`import torch` 的用例在 managed Python 下无 torch（见项目记忆）。
纯函数 / 前端符号断言可用 managed Python + `node --check` + `tests/js/*.check.js`。
