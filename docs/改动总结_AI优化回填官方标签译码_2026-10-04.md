# 改动总结 · AI 优化回填「官方标签」译码（2026-10-04）

## 用户报告

跑「✨ AI扩写+优化 / ✨ 提示词优化」时，注入提示词框的**有时是 `picture1` 这种格式**，
而不是 `@素材名` → 有些时候识别不了素材。

用户的心智模型：`素材名 → picture1 → 素材名`，认为这条编译链"理论上不会出错"。

## 断点：不是用户以为的那一跳，而是它旁边多出来的"官方标签"这一层

用户以为"发给 LLM 的是 picture1"，实际那条链用的是 **`@标注`（`图片1`）**，不是 `Picture 1`：

```
提示词框（磁盘）        @女主.png
   ↓ toLLMText / marksToText        出参换码
发给 LLM 的正文          @图片1        ← 标注：池内全局编号，只活在"提示词 ⇄ LLM"这一跳
   ↓ LLM 返回
LLM 产出                @图片1  ← 期望；但 system prompt 要它写 <Picture N>（官方 ref-en.txt 规则）
   ↓ fromLLMText / textToMarks      回参换码
写回提示词框            @女主.png  ← 期望
```

**问题出在 LLM 返回那一格**：

- `optimizer.build_system_prompt`（照官方 ref-en.txt）要求"镜头正文里一律用 `<Subject N>` /
  `<Picture N>` 等官方标签指代参考内容，不要写文件名"；
- 而 `textToMarks` **只认标注**（官方 token 被当成"另一层编号"，故意不动）；
- 两边一撞 → 模型写下的 `<Picture N>` **原样落盘**：
  1. 提示词框里出现 `picture1`（用户看到的）；
  2. `refsFromText` 只扫 `@素材名`，扫不到 → **本段引用为空 → 素材静默不进模型**。

更隐蔽的一点：前端 `collectSegMedia` 的 note 写的是"正文里直接写 @名字、**不要写 `<Picture N>`**"，
与 system prompt **正好相反**。这个矛盾**消不掉** —— 官方格式要官方标签，素材挂载要 `@素材名`。
所以修复方向只能是**回填兜底**，而不是去统一口径。

## 修复（回填多译一跳）

| 文件 | 改动 |
|---|---|
| `web/h3_prompts.js` | 新增 `officialToMarks(text, media, pool)`：官方标签按**送进 LLM 的 media 顺序**（与执行期 `nodes._kind_tokens` 同口径：帧锚前置 + 参考素材顺延，各类别独立从 1 编号）译回 `@素材名`。译不出（编号越界 / 素材已不在池里）**原样保留**，不猜不吞。`<Subject N>` **不译**（抽象可见内容标签，不是素材引用）。 |
| `web/h3_director.js` | `fromLLMText(text, pool, media)` 加第 3 参（**不传 media 退化成旧行为**，老调用点/单测不受影响）；两条 AI 链 `runOptForSegment` / `runExpandOptimizeForSegment` 都传 `mm.media`；回填告警从"编号越界"改成"**残留官方标签**"（更准，覆盖"素材不在池里"这种情况）。 |

改动后：LLM 写 `@图片1` → `textToMarks` 译；LLM 写 `<Picture 1>` → `officialToMarks` 译。
两条路都通，矛盾不再是 bug。
