# 改动总结：二采自定义 Sigmas + 一采槽改名（2026-10-12）

来源：用户要求「加个二采自定义 sigmas 的接口，现有的自定义 sigmas 接口变成一采自定义 sigmas 接口」。

原「自定义Sigmas」槽（2026-09-21 加，见 `docs/HyperFlow适配与自定义Sigmas.md`）只作用于
**一采**（基础链）。二采（潜空间放大高清精化）当时走的是自己的 `common_ksampler(steps=n,
denoise=σ₀)` 低强度精化路径，没有外部 sigma 表的口子 —— 于是「二采另接一份带自己 sigma 表的
少步蒸馏权重」这条组合无处可接。本次把它补上。

## 二、二采接表后的行为表

| 二采面板项 | 接表后 | 理由 |
|---|---|---|
| 去噪（σ₀） | ❌ 失效 | 精化起点改由**表首值**决定 |
| 精化步数 | ❌ 失效 | 实际步数 = **表点数 − 1** |
| 调度器 | ❌ 失效 | 表即调度（`KSampler.sample` 里 `if sigmas is None` 才用现算的） |
| 多轮递降（passes/decay） | ❌ 让位 | 表本身就是整条精化轨迹，再叠轮次没有语义 |
| 增益重试（retry） | ❌ 让位 | 它要从 σ₀+0.1 **现推**一张 cascade 表，而表是外部给的，推不出来 |
| 采样器 | ✅ 生效 | 与一采同口径：`sampler_name` 仍传给采样器 |
| shift / STG | ✅ 生效 | 激活窗口按**表首值**算（`_stg_model` 的 `sigma_start` 参数） |
| 时序分块 / 空间 tile | ✅ 生效 | 每块各自跑整张表（表首值即每块的加噪起点） |

**为什么不让 `denoise` 继续参与**：`comfy.sample.sample` 在 `sigmas` 非 None 时**忽略** `denoise`
（它只影响 `KSampler.__init__ → set_steps` 现算的那张表，而那张表已被外部表顶掉）。
所以传 `denoise=表首值` 是**零代价的语义对齐** —— 它唯一被消费的地方是 STG 的激活窗口。

**空表/坏表**（`sigmas_steps` 取不到长度）当作没接：宁可走回原路径，也不拿一张读不出来的表
把整条链打停。

## 三、指纹口径（改这个最容易出事故）

两条铁律，与一采同源：

1. **未接时不加键。** `_hash_params` 是 `json.dumps(sort_keys=True)` 的输入，
   「多一个键」就是新指纹 —— 会让既有项目的高清记录全部判失效重做。
2. **接了才加键。** 表指纹（`fingerprint_tag`）由 `nodes.py` 写进 `up_cfg["sigmas"]`，
   于是 `record_stale()` 在**调用 `render_segment` 之前**就判得出「换表 = 该段重做」。

另外三项**退出指纹**：接表后 `passes/decay`、`retry`、`scheduler` 在采样侧已失效，
拨它们不该触发整链高清重做（`_hash_params` 里用 `and not _has_sig` 逐个挡掉）。

⚠ 传张量的位置很关键：**cfg 必须保持可 JSON 序列化**（它进 manifest），所以
**表指纹进 cfg、张量走形参**，两者不混。

### 3.1 「表真能用吗」必须只有一个判据（复核时收紧）

写键与「按不按表采样」原本是两处各判一次，空表/坏表会落到错位状态：
`fingerprint_tag` 对坏表返回 `"custom"` → 指纹变了；而采样侧取不到步数 → 回落原路径。
结果就是**既有高清段被判失效全部重做，画面却一个像素没动**（纯白做）。

现在统一为 `sigmas_adapter.sigmas_usable`（点数 ≥ 2）一处判据，三处共用：
`nodes.py` 写键、`upscale.render_latent` 采样分支、`upscale.render_segment` 报告回显。

## 四、两个边界（复核补测）

| 情形 | 二采受影响吗 | 一采受影响吗 |
|---|---|---|
| **只接一采表**，二采不接 | **零影响** | 按表走 |
| **只接二采表**，二采没开 | 零影响（本来就没跑） | 零影响 |

依据：

- **只接一采表**：一采表的张量只在一采采样点用（`sigmas=一采自定义Sigmas`）；
  二采指纹只认 `up_cfg["sigmas"]`，而那个键**只由二采槽写入**。最强守卫是
  「`upscale.py` 里不出现『一采自定义Sigmas』这个名字」——一旦出现就说明渗了。
- **只接二采表但二采没开**：`up_cfg = upscale.parse_state(ds)` 在二采关着时就是
  `None` → 写键那句在 `if up_cfg:` 块内、执行不到；`render_segment` 也受
  `if not (up_cfg and use_ckpt)` 守卫不会被调用。张量进了执行图但没人消费。

两条都有报告行兜底，不会静默：坏表 →「接了表但读不出有效步数…已按未接处理」；
二采没开 →「已接线但本次二采未启用…该表未生效」。

**唯一的非零成本**：接线让上游表节点进了执行图（如 `ManualSigmas` 会照跑）。
不需要时 bypass（Ctrl+B）即可 —— 纯连线槽不参与执行。

### 4.1 复核顺带更正的既有文档错误

`docs/HyperFlow适配与自定义Sigmas.md` 旧文写「**换表 = 重做**（`ckpt_params["sigmas"]`）」。
这是 2026-09-21 的口径，当时 `fingerprint()` 还参与自动项目目录命名；2026-10-12
「链参数不再强制整链一致」之后自动项目目录固定为 `h3chain`、`fingerprint()` 退化为
诊断用，**基础链参数（含一采表）已不再触发任何重做**，只由 `checkpoint.assert_match`
报告一句「参数已变更…不会因此重做」。已更正，并补上「一采/二采重做口径不对称」的说明：

| | 改参数后已存档段会重做吗 | 机制 |
|---|---|---|
| 一采表 / 一采步数 / 一采采样器 | ❌ 不会（要手动「重跑起始段」） | 只进 `manifest.params`，只报告 |
| 二采表 / 二采去噪 / 二采步数 / 二采采样器 | ✅ 会（高清段自动重渲染） | `upscale.params_hash` → `record_stale` |

不对称是两边既有设计各自成立（基础段贵且与盘上张量无耦合 → 不重做；二采是便宜的
再渲染 → 参数变即重做）。二采表跟着二采那一侧走。

### 4.2 复核顺带修掉的误导文案

「二采未接独立模型」那条提示原本固定写「二采用的是二采自己的步数/调度器
（**不是蒸馏表**），轨迹对不上」。二采自己接了表之后这句就不成立了 —— 现在按
`_up_sig_usable` 分两种说法；同理「二采未指定采样器/调度器，会沿用主链值」这条
也只对没接表的情形成立（接表后调度器已失效）。

## 五、兼容性：为什么改名是安全的

输入连线的坐标是**位次**（工作流序列化 `inputs` 的数组序；前端 `configure` 按位次重建），
不是名字。本次：

- 「一采自定义Sigmas」占的**正是**旧「自定义Sigmas」那一位（`io.Sigmas.Input` 的位置没动）；
- 「二采自定义Sigmas」加在它**后面**（新的一位）。

所以旧工作流里接在「自定义Sigmas」上的线，载入后仍落回「一采自定义Sigmas」；
`widgets_values` 仍是 30 项（两个槽都是纯连线槽，不占位）。
`tests/js/link_repair_check.js` 的按名搬线机制对本次改动零动作（位次没漂）。

## 六、报告与控制台

主节点报告新增三类行：

- 配置回显：`二采自定义 Sigmas：N 步 @ σ≈0.35/0.28/0.19/0.09/0`（写明「去噪/精化步数/调度器」
  已忽略、采样器仍生效、多轮递降与增益重试是否让位、二采面板调度器为何无效、adaptive 为何失效）；
- 坏表行：`接了表但读不出有效步数（空表 / 坏表，点数 < 2）——已按「未接」处理`；
- 未生效行：`已接线但本次二采未启用（面板关闭 / 被跳过）——该表未生效`。

每段的报告行（`段N 二采：…`）接表时按**表自己的**步数与 σ 序列回显，并标「（自定义σ表）」；
采样器一项也改口径（只报采样器，不再报已失效的调度器）。控制台另有
`[H3二采] 段N：使用二采自定义 sigma 表（N 步 · σ≈x→0）` 一行。

新增守卫（`tests/test_sigmas_adapter.py`）：

- `test_sigmas_inputs_are_last_and_link_only` —— 两个槽都在末尾 widget 之后、都 `optional=True`、
  一采槽在二采槽之前（位次=连线坐标）；
- `test_second_pass_channel_is_wired_end_to_end` —— **四段接线一个不漏**：
  两个入口都声明形参 → `render_segment` 透传 → 精化真的走 `ksampler_with_sigmas` →
  `nodes.py` 传张量且写指纹。历史同类 bug：声明了形参没往下传（埋点 `_vram` 就这么漏过）；
- `test_second_pass_fingerprint_only_when_wired` —— 「接了才加键」+ 三项让位项退出指纹；
- `test_sigmas_usable` —— 空表 / 1 点表 / 坏表都判「不可用」（写键与采样分支的同一判据）；
- `test_first_pass_table_never_leaks_into_second_pass` —— **边界①**：`upscale.py` 里不出现
  「一采自定义Sigmas」这个名字（一旦出现就是渗了）；
- `test_second_pass_table_is_inert_when_upscale_off` —— **边界②**：写键嵌在 `if up_cfg:` 内、
  判据算在块外、两句未生效提示都在。
