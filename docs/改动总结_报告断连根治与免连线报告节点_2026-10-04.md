# 改动总结：报告线断连**根治** + 免连线报告节点（2026-10-04）

用户报告：**每次重启 ComfyUI，导演台和预览任意（PreviewAny）的节点都会断连**，
希望解决；「如果实在不行就弄一个专门的预览报告节点」。

两件事都做了：① 把根因除掉（不用你做任何事）；② 按你说的做一个**免连线**的报告节点。

---

## 一、根因（前四轮都没除根，因为方向错了）

### 现象链条

1. **输出槽位次由 schema 决定，不由存档决定。** 1.53.6 真机（8189/8190）实测：运行时输出槽
   永远按 `nodes.py` 的 `outputs` 顺序建，workflow JSON 里序列化的 `outputs` 数组**对布局无效**。
   （输入侧相反 —— 输入由序列化数组重建，所以输入侧有前端 realignment 兜底，输出侧没有。）
2. rev3.2 把「帧率」插在「音频」和「报告」之间 → 「报告」从 **2 号位被挤到 3 号位**。
3. 而 rev3 之前存下的工作流（含用户手上这份 `user/default/workflows/新版默认工作流.json`）
   里，报告线写的是 `origin_slot = 2` → 载入后那根线落到 **2 号位的「帧率」**上。
4. 「帧率」是导演台的**停机场槽**（`H3_DESK_HIDE_SLOTS`，画布上不画它）→
   **画布上那根线看着还连着，下游 PreviewAny 的「源」实际收不到** = 用户说的「断连」。

### 为什么 rev3.3 的「载入后按名搬线」没能收尾

`repairMisplacedOutputLinks` 本身是对的，但它是**创可贴**：每次存档又会把 `origin_slot`
按当时的位次写回去；搬线只要错过一次时机（浏览器缓存旧 JS / 载入时序 / 前端 remint），
断连就复现。**只要位次本身是错的，就永远在打地鼠。**

### 根治

**让位次本身永远对** —— `nodes.py` 的 `outputs` 改成：

```
图像 / 音频 / 报告 / 帧率
```

「帧率」这个停机场槽排到**末位**，「报告」钉回 **2 号位**。于是：

- rev3 之前的老存档（报告 @2）→ 自动正确；
- 新存档（报告 @2）→ 自动正确；
- 隐藏/裁剪末位槽再也不会挪动可见端口的位次。

旧的按名搬线逻辑**保留**，降级为「只救历史错位文件」的兜底。

## 三、免连线报告节点 `H3RunReport` 怎么工作

- **一个输入端口都没有** → 结构上不存在「断连」这个故障模式。
- 报告文本**本来就落盘**了：`checkpoint.save_state` 每跑一段写
  `output/h3_projects/h3chain_state.json` 的 `"report"` 字段。
- 前端读插件自己的接口 `GET /h3chain/projects → state.report`
  （**不走** `/api/view` —— 那是可启发式缓存的 FileResponse，而这个文件每跑一段就改写，
  会反复拿到旧指针，`routes.py::list_projects` 的注释里为这个坑留过记录）。
- 刷新时机：节点建立/载入工作流、每次 `execution_success`、手动点「🔄 刷新报告」。
- **不是 OUTPUT_NODE、也没有输入** → 默认不进执行图，纯展示；
  仍留一个「报告」输出，接进图里当普通节点也能用（`IS_CHANGED` 恒 nan 强制重读）。
- 用法：把接在「报告」上的 `PreviewAny` 删掉，换成 `H3RunReport`，**不接任何线**。

## 五、用户侧要做的事

- **什么都不做**：重启 ComfyUI 后，老工作流里的报告线会自动连对（位次自洽了）。

  不用接任何线，位置随意摆。
