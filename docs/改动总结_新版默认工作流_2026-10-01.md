## 二、工作流结构（相对 rev 2）

**新增链路：**
- 一采加 LoRA：`UNET(int8) → LoraLoaderModelOnly(minimax_h3_turbo_v4_step600_ema_pruned, 1.0) → LoraLoaderModelOnly(Motion_Repair_V2, 0.6) → ModelAttentionBackend → BlockSparseAttention → 主节点`。
  turbo 配套少步采样，模板「步数」从 20 改 8。
- 独立二采链（首次进默认工作流）：`UNETLoader(w6a8) → ModelAttentionBackend → BlockSparseAttention → 主节点「二采模型」槽`，专做高清精化二采；不接该槽 = 沿用一采模型（旧行为不变）。

**导演台状态 JSON（主节点 widget 27 位）：**
- 段结构换锚定双轨 schema（`auto_ref / auto_seq / frame_refs / latent_save / latent_ref / tail_src / anchors`），与 `defaultSegment()` 同构；
- 二采：跟随生成 · 1.4× · denoise 0.35 · steps 4 · shift 6 · euler/simple · arch auto · time_bias 0；
- 语义桥：开 · BUNNY V2 · alpha 0.15 · 全量过桥；
- AI 优化：GLM api 预设（`open.bigmodel.cn` / `glm-5.3-flashx` / cfg_ver 3）——与 `optDefaultSettings()` 全等，Key 留空待用户自填。

**端口结构（rev3→rev3.2 两轮真机实证后的最终口径）：**

导演台把 5 个端口收进「停机场」（`H3_DESK_HIDE_SLOTS`：起始视频/起始视频音轨/帧率），
而 1.53.6 前端对主节点的槽位处理是**输入/输出不对称**的（真机 8189/8190 实测）：

- **输入侧**：运行时由序列化数组**重建**——模板给 6 实槽（`视频VAE/音频VAE/模型/文本编码器/二采模型/自定义Sigmas`），连线表按这个位次写（二采模型=4），前端再把控件槽追加在尾部；起始视频/起始视频音轨不出现在画布。
- **输出侧**：运行时按 schema 建 4 槽（图像/音频/帧率/报告），**但前端会把「未接线的停机场槽」从数组里裁掉**——载入时序不同，3 槽/4 槽都会出现。按位次写输出连线本质上不可靠（rev3 首版 3 槽制 @2 → 落到不存在的槽上断线；rev3.1 4 槽制 @3 → 落到「帧率」上，两轮都栽在这里）。输入侧前端有 realignment 兜底，**输出侧没有**。

rev3.2 的组合拳：

1. 模板 outputs 写 **schema 4 槽制**（图像/音频/帧率/报告），报告线 origin_slot=3（schema 位次）；
2. 导演台新增**输出侧按名搬线**（`savedOutputIntents` + `repairMisplacedOutputLinks`）：意图从存档 `outputs[].links` 收（名字↔link id 同源），运行时按「目标输入端口的领线」定位连线（remint 后的 id 也能找到），把 origin_slot 修正到按名找到的端口；无论本机是 3 槽还是 4 槽，报告线都接回「报告」。老 3 槽制导出（报告@2 落到帧率上）同样被救；
3. `paintDeskNode` 的 `computeSize` 过滤改 try/finally 归还——原先原函数在载入窗口抛异常会把过滤后的 outputs 数组永久泄漏（端口整个消失，正是老会话存出 3 槽制文件的来路）；
4. 三处触发点与跨项目登记同步（`pendingOutputIntents` = derived 作用域）；`H3D_VER` → `20261001+link-repair-io`（控制台可确认新代码生效）。
- `自定义Sigmas` 为纯连线槽（无 widget、不占 30 位布局），模板默认空置

## 三、出厂链参数（三处同源）

| 参数 | 旧默认 | 新默认（rev 3） |
|---|---|---|
| 百万像素 | 0.5 | **1.0** |
| 每段时长 | 5.0 | **8.0** |

| 桥帧门控 | 标注 | **关闭** |

同步位置（改默认值必须三处同改）：
1. `nodes.py define_schema` 的 `default=`（新建节点的出厂值）；
2. `web/h3_director.js` `CHAIN_DEFAULTS`（右栏「↺ 恢复默认」/ 顶栏「全局重置」的落值）；
3. `web/h3_default_workflow.js` `widgets_values`（+ `example_workflows` 同款）。

未动的默认：种子 0、存档目录空（节点级语义不变；模板里带用户的具体值：fixed 种子、项目 "1"）。
`defaultBridge()` / `defaultUpscale()`（语义桥、二采的「恢复默认 / 全局重置 / 新建项目」基准）
**2026-10-01 起同样与默认工作流同源**（用户明确要求）：语义桥 = 开 · BUNNY V2 · alpha 0.15 ·
全量过桥；二采 = 跟随生成 · 1.4× · 去噪 0.35 · 精化 4 步 · shift 6 · euler/simple。
注意 `getDs` 对**缺键的老存档**另有保守填充（桥=关、二采=关），不经过这两个函数 ——
既有项目不会被静默改写，只有「恢复默认 / 全局重置 / 新建项目」走新口径。

## 四、连锁兜底值（跟随 8s 默认）

| 位置 | 旧 | 新 | 原因 |
|---|---|---|---|
| `h3_director.js snapFrames()` 无效秒兜底 | 124 帧 | **192 帧** | 注释口径「与后端默认一致」，8s=17×11+5 |
| `h3_director.js segmentSeconds()` 最后兜底 | 5.0s | **8.0s** | 节点控件读不到时跟随出厂默认 |
| `perf.py refine_temporal_chunk` | 124 | **192** | 语义是「默认=与主链每段时长同宽（整段不切）」，默认时长改 8s 后 124 会把每段切两块 |
| `h3_director.js` 精化分块 hint / 「视频延续」恢复默认确认文案 | 5.17 秒 / 标注·自动 | 8 秒 / 关·关 | 文案与落值一致 |
