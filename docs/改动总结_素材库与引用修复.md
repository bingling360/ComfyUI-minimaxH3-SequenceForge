# 改动总结：素材库 / 资产引用 五处修复

日期：2026-09-13（对应一轮试用反馈）

| # | 现象 | 根因 | 改法 |
|---|---|---|---|
| 1 | 换项目后提示词框「资产引用」栏不更新 | `hydratePool` 只做**增量追加**，旧池永不清理；切项目/改名/删除后残留 | 池子改为**按 manifest 整体重建**（`poolFromManifest`，与 `switchProject` 共用），同名以 `asset_links` 胜出 |
| 2 | 点引用 chip 不即时变绿，要切换一下才对 | 点击后 `insertAtCursor` 让 textarea 获得焦点 → 中栏「编辑中不重建」守卫跳过重绘 | 点完先按写回 widget 后的真实状态**就地重画 chip**（`paintAll`），再排刷新；顺带显示「已引用 N（图/视/音 上限）」 |
| 3 | 引用声明不是官方格式 | 缺 tag 时注入自造的 `[References]\n<Picture 1> = 别名` 赋值表 | 改成官方 `subject_definitions` 句式：`<Picture 1> is the reference image "女主".` |
| 4 | 素材库改名点了没反应 | ① `asset_links.alias` 与 `manifest.assets.label` 只改一处，显示名取的是后者；② 前端用 `window.prompt`，部分壳会吞掉 | 后端**两处同名都改** + 重名预检；前端换自建输入弹窗（`askText`） |
| 5 | 上传只进全局库 | `library_upload` 的 `mirror` 只在 JSON 分支读，multipart（浏览器上传）永远读不到 | 新增 `dest=global/project/finals`，按钮文案跟随当前 scope；成片落 `finals/`（`library.store_to_finals`） |
| 6 | 星级要进预览器才能看/改 | 瓦片只有只读角标 | 瓦片常驻 5 星条（点即设分，点当前星级=清除），预览器复用同一组件 |
| 7 | 段卡勾了引用，素材库却显示「没被引用」 | `compute_refs` 只读 `manifest["segments"]`，但导演台回写的 refs 落在 `manifest["seg_fields"]` | 两处都读（按全局槽位与 prompts 同索引），顺带把 `tail_src` 也合并 |

## 关键实现

### 池子权威化（web/h3_director.js）

```js
poolFromManifest(mf, links)   // manifest.assets + asset_links -> 规范池子
poolSig(pool)                 // 指纹，不变就不写 widget（不打断打字）
hydratePool(force)            // dir 变化强刷；_poolDir/_poolRev 节流
```

- `switchProject` 与 `hydratePool` 现在**共用同一个构造函数**（此前两处口径不同 → 切项目偏差）。
- 素材库的删除/上传也会 `notify()` 通知导演台刷新（此前删除不通知）。

### 上传落点（routes.library_upload）

```
dest=global   → 只进全局库
dest=project  → 全局库一份 + 项目 assets/ 一份（登记清单，可 @别名 引用）
dest=finals   → 全局库一份 + 项目 finals/ 一份（目录扫描即见，不登记）
```
前端 `dest` 由当前 scope 推导（全局库/项目资产/成片库），按钮文案与提示同步切换。

### 改名（routes.lib_alias）

1. 重名预检：撞已有 label/alias → 400 `DUP_ALIAS`（`@别名` 是引用命名空间）。
2. `asset_links.alias` 与 `manifest.assets.label` **都改**（返回 `renamed:{link,asset}`）。
3. 都没命中 → 改全局库 `orig_name`。

## 测试

- 新增 `tests/test_library_actions.py`（改名双写 / 重名拦截 / 三种落点，multipart 替身）。
- `tests/test_library.py::test_store_to_finals`（成片落点，含同名 _2 与可见性）。
- `nodes._reference_tags_minimal` 官方句式断言更新（`test_ref_semantics.py`）。
- `test_review_fixes.py::test_roles_sync_points` 断言改到新构造函数上。

跑法：`python -m pytest tests -q --ignore=tests/test_rework_v2.py`

# 第二轮（同日）：引用次数 + 首尾帧入口迁移

## 8. 同一素材可在一段里引用多次（计数）

需求原话：「点了一次以后出现数字 1，点第二次显示引用 2，且要以 H3 官方格式正确生效」。

**语义定案**：编号是素材的身份，不是出现次数。

| 层 | 表示 | 说明 |
|---|---|---|
| `segments[i].refs` | 允许**重复元素**（`["女主","女主","背景"]`） | 重复次数 = 引用次数（UI 计数与持久化真相） |
| 编号 | 同一素材只占一个 `<Picture k>` | `_kind_tokens` / `compile_refs` 对重复标签去重后编号 |
| 正文 | 写 N 个 `@女主` | 编译后同一个 `<Picture 1>` 出现 N 次 —— 官方格式里"同一参考图多处出现"就是这么写的 |
| 上限 | 素材个数按官方 9/3/3（**去重**算）；单素材重复另有软上限 `REF_REPEAT_MAX=9` | 重复不占额度，不会误报超限 |

改动点：

- `web/h3_director.js`：`toggleSegmentRef` 拆成 `addSegmentRef`（+1，正文补一个 `@标签`）与
  `removeSegmentRef`（−1，正文删掉最后一个 `@标签`，减到 0 即从本段移除）；
  chip 显示 `✓@女主 ×2`，旁边多一个「−」小按钮；计数器显示「已引用 N 个素材（共 M 次…）」。
- `nodes._kind_tokens`：重复标签只编号一次（防御性，任何调用方传重复都安全）。
- `asset_store.compile_refs`：重复引用合并到同一条 block（`use` 取首个非空）。
- `asset_hub.check_segment_refs`：按去重后的素材个数卡上限。
- `projects._clean_seg_field`：refs 原样保留重复项（**不能**去重，否则计数丢失）。

## 9. 首尾帧标注从素材库迁到提示词框

需求原话：「不应该在素材库里面标注，而是在提示词框资产引用那里有两个按钮，可以上传在项目里面的图片」。

- **素材库**：瓦片上的「首帧图/尾帧图」按钮与右键菜单项删除（旧标注仍显示徽标并可点击查看提示；
  后端 `lib_role` 与链级 `chain_head_label/chain_tail_label` 保留，旧项目照常生效）。
- **导演台 · 每段资产引用栏**：新增「＋首帧图」「＋尾帧图」两个按钮 → 弹窗里挑项目内的图片，
  或「＋ 上传一张」（走 `dest=project`，全局库一份 + 项目 assets/ 一份）。
- **段字段**：`segments[i].frame_img = {first, end}`（项目内相对路径，白名单清洗）。
- **执行期生效**（`nodes.py`）：
  - 首段的首帧图 → 提升为 `首帧图片` → i2v 起手帧（官方 I2VA 指令行照旧注入）；
  - 末段的尾帧图 → 提升为 `尾帧图片` → FL2VA 剧情终点锚；
  - 其余段 → 段头/段尾身份锚 keyframe（按文件缓存编码，各文件只编一次）；
  - 段级优先于库内旧标注；换图进逐段哈希（`fimg:`），从该段起重做。
- **关键取舍**：首/尾帧图**不**自动进本段 `refs`。加了 refs 会让首段走 Ref2V（多参）分支，
  反而丢掉 i2v 起手帧语义 —— 锚点是锚点，素材引用是素材引用。

新增测试：`test_repeat_refs_keep_single_token`、`test_parse_frame_imgs`（AST 抽 shipped 纯函数）、
`test_compile_refs_repeat_dedupes_token`、`test_check_segment_refs_repeat_not_over_limit`。

# 第三轮（同日）：提示词框内联绿框 + 锚定方式 + 桌面端输入

## 10. 引用在提示词框里显示成内联绿框

`web/h3_director.js` 新增 `createPromptEditor()`：段提示词框从 `<textarea>` 换成
`contenteditable` 富文本编辑器，`@别名` 渲染成**内联绿框**（`span.h3d-rtag` + `✕` 按钮）。

- 对外暴露 **textarea 兼容接口**（`value` getter/setter、`focus`、`addEventListener`、
  `selectionStart`、`setSelectionRange`、`dataset`、`placeholder`、`dispatchEvent`…），
  所以 @补全、AI 优化、编译预览这些既有代码**零改动**继续可用。
- 绿框是 `contenteditable=false` 的原子节点：光标进不去、退格整块删。
- 序列化：绿框还原成 `@别名`，`<br>`/块级元素还原成换行（有 node 真跑测试）。
- 粘贴只收 `text/plain`（防 HTML 注入）。
- 打字停顿 700ms 自动把裸 `@别名` 收成绿框（IME 组合中不动 DOM，防打断中文输入）。

## 11. 「取消参考清不完」的真正修法：正文 = 唯一真相

之前 refs 与正文是**两份状态**（refs 里 3 条、正文里 2 个 `@标签`，谁对？），所以怎么删都像没删干净。

现在 `syncRefsFromText()` 让 `segments[i].refs` **由正文里的 @别名 序列推导**：

| 动作 | 结果 |
|---|---|
| 点 chip（+1） | 正文插一个绿框 → refs 自动同步 |
| 绿框 `✕` / chip 旁 `✕` | 正文里该素材的**全部**绿框一次清掉 → refs 归零 |
| 手动删正文里的绿框 | 退格即删，refs 跟着掉 |
| 手动打 `@别名` | 700ms 后收成绿框，refs 同步 |
| 清空提示词 | refs 一并清空（此前留着 = 「正文没标签、引用栏还亮着」） |

写入点只有一处：`setPromptText()`（内部调 `syncRefsFromText`），所有编辑路径都经过它。

## 12. 引用语 → 「锚定方式」（先选方式，再点素材）

原交互是"选中一个素材 → 再从下拉里挑句式插到光标处"，顺序反了。现在：

- 下拉变成常驻模式：`锚定方式：无（只插 @标签）` / `主角出场` / `场景还原` / `风格参考` …
  选择按段记住（`_refTpl`），重绘不丢。
- 选中方式后**点参考素材**，该素材就按这个方式写进正文（例：`场景以 @阿依的家 为准，延续其环境、光照与空间布局`）；
  不选 = 只插裸 `@标签`，用法自己在正文里写。
- 每条模板同时带**官方字段语义**：

| 模板 | 官方 retention 标记 | subject_definitions 角色句 |
|---|---|---|
| 主角出场 | fully_preserved | the main subject; keep identity… |
| 配角出场 | fully_preserved | a supporting character… |
| 场景还原 | partially_preserved | the environment reference; keep layout… |
| 风格参考 | weak_reference | a style reference; keep palette… |
| 镜头参考 | weak_reference | a camera-movement reference… |
| 音频参考 | weak_reference | an audio reference… |

**回答「引用语符合官方 skill 格式吗、有用吗」**：句式文本**有用**（`<Picture k>` tag + 语义句
都会进模型），但官方把"怎么锚定"写在**字段**里 —— `subject_definitions`（每个引用是什么角色）
与 `retention_analysis`（`fully_preserved` / `partially_preserved` / `weak_reference`）。
所以模板现在会把角色句与保留标记一起写进**具象化结构**（`prompt_v2.references` / `.retention`），
六字段编译时进官方字段；本段没有 `prompt_v2` 时**不创建**（免得把三字段段悄悄切成六字段），
那时只有句式文本生效。

## 13. ComfyUI 桌面端输入框打不进字（兜底）

桌面端（Electron）偶发：进入后不刷新，所有输入框都打不进字（窗口/画布占着键盘焦点）。
`installDesktopFocusFix()` 三招兜底（正常情况不触发）：

1. 点输入框时若焦点还停在 `body`/`canvas`，主动再 focus 一次（含下一拍重试）；
2. 输入框内的按键在捕获阶段 `stopPropagation`，不被画布热键处理吃掉；
3. 顶栏加「⌨ 输入修复」按钮，手动把焦点抢回来（刷新页面同样有效）。

> 注：这是桌面端宿主的焦点问题，扩展只能兜底；若仍复现，请把「输入修复」按钮与刷新前后的
> 控制台日志一并反馈。
