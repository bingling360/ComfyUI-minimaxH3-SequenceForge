# 改动总结：素材库 / 资产引用 五处修复

日期：2026-09-13（对应一轮试用反馈）

| # | 现象 | 根因 | 改法 |
|---|---|---|---|
| 1 | 换项目后提示词框「资产引用」栏不更新 | `hydratePool` 只做**增量追加**，旧池永不清理；切项目/改名/删除后残留 | 池子改为**按 manifest 整体重建**（`poolFromManifest`，与 `switchProject` 共用），同名以 `asset_links` 胜出 |
| 2 | 点引用 chip 不即时变绿，要切换一下才对 | 点击后 `insertAtCursor` 让 textarea 获得焦点 → 中栏「编辑中不重建」守卫跳过重绘 | 点完先按写回 widget 后的真实状态**就地重画 chip**（`paintAll`），再排刷新；顺带显示「已引用 N（图/视/音 上限）」 |
| 3 | 引用声明不是官方格式 | 缺 tag 时注入自造的 `[References]\n<Picture 1> = 别名` 赋值表 | 改成官方 `subject_definitions` 句式：`<Picture 1> is the reference image "女主".` |
| 4 | 素材库改名点了没反应 | ① `asset_links.alias` 与 `manifest.assets.label` 只改一处，显示名取的是后者；② 前端用 `window.prompt`，部分壳会吞掉 | 后端**两处同名都改** + 重名预检；前端换自建输入弹窗（`askText`） |
| 5 | 上传只进全局库 | `library_upload` 的 `mirror` 只在 JSON 分支读，multipart（浏览器上传）永远读不到 | 新增 `dest=global/project/finals`，按钮文案跟随当前 scope；成片落 `finals/`（`library.store_to_finals`） |
| 6 | 星级要进预览器才能看/改 | 瓦片只有只读角标 | 瓦片常驻 5 星条（点即设分，点当前星级=清除），预览器复用同一组件 |
| 7 | 段卡勾了引用，素材库却显示「没被引用」 | `compute_refs` 只读 `manifest["segments"]`，但导演台回写的 refs 落在 `manifest["seg_fields"]` | 两处都读（按全局槽位与 prompts 同索引），顺带把 `tail_src` 也合并 |

## 关键实现

### 池子权威化（web/h3_director.js）

```js
poolFromManifest(mf, links)   // manifest.assets + asset_links -> 规范池子
poolSig(pool)                 // 指纹，不变就不写 widget（不打断打字）
hydratePool(force)            // dir 变化强刷；_poolDir/_poolRev 节流
```

- `switchProject` 与 `hydratePool` 现在**共用同一个构造函数**（此前两处口径不同 → 切项目偏差）。
- 素材库的删除/上传也会 `notify()` 通知导演台刷新（此前删除不通知）。

### 上传落点（routes.library_upload）

```
dest=global   → 只进全局库
dest=project  → 全局库一份 + 项目 assets/ 一份（登记清单，可 @别名 引用）
dest=finals   → 全局库一份 + 项目 finals/ 一份（目录扫描即见，不登记）
```
前端 `dest` 由当前 scope 推导（全局库/项目资产/成片库），按钮文案与提示同步切换。

### 改名（routes.lib_alias）

1. 重名预检：撞已有 label/alias → 400 `DUP_ALIAS`（`@别名` 是引用命名空间）。
2. `asset_links.alias` 与 `manifest.assets.label` **都改**（返回 `renamed:{link,asset}`）。
3. 都没命中 → 改全局库 `orig_name`。

## 测试

- 新增 `tests/test_library_actions.py`（改名双写 / 重名拦截 / 三种落点，multipart 替身）。
- `tests/test_library.py::test_store_to_finals`（成片落点，含同名 _2 与可见性）。
- `nodes._reference_tags_minimal` 官方句式断言更新（`test_ref_semantics.py`）。
- `test_review_fixes.py::test_roles_sync_points` 断言改到新构造函数上。

跑法：`python -m pytest tests -q --ignore=tests/test_rework_v2.py`
（隔离 venv 缺 av/torch，media_stream / transcode 那 5+6 条是环境缺依赖，与本次改动无关）

# 第二轮（同日）：引用次数 + 首尾帧入口迁移

## 8. 同一素材可在一段里引用多次（计数）

需求原话：「点了一次以后出现数字 1，点第二次显示引用 2，且要以 H3 官方格式正确生效」。

**语义定案**：编号是素材的身份，不是出现次数。

| 层 | 表示 | 说明 |
|---|---|---|
| `segments[i].refs` | 允许**重复元素**（`["女主","女主","背景"]`） | 重复次数 = 引用次数（UI 计数与持久化真相） |
| 编号 | 同一素材只占一个 `<Picture k>` | `_kind_tokens` / `compile_refs` 对重复标签去重后编号 |
| 正文 | 写 N 个 `@女主` | 编译后同一个 `<Picture 1>` 出现 N 次 —— 官方格式里"同一参考图多处出现"就是这么写的 |
| 上限 | 素材个数按官方 9/3/3（**去重**算）；单素材重复另有软上限 `REF_REPEAT_MAX=9` | 重复不占额度，不会误报超限 |

改动点：

- `web/h3_director.js`：`toggleSegmentRef` 拆成 `addSegmentRef`（+1，正文补一个 `@标签`）与
  `removeSegmentRef`（−1，正文删掉最后一个 `@标签`，减到 0 即从本段移除）；
  chip 显示 `✓@女主 ×2`，旁边多一个「−」小按钮；计数器显示「已引用 N 个素材（共 M 次…）」。
- `nodes._kind_tokens`：重复标签只编号一次（防御性，任何调用方传重复都安全）。
- `asset_store.compile_refs`：重复引用合并到同一条 block（`use` 取首个非空）。
- `asset_hub.check_segment_refs`：按去重后的素材个数卡上限。
- `projects._clean_seg_field`：refs 原样保留重复项（**不能**去重，否则计数丢失）。

## 9. 首尾帧标注从素材库迁到提示词框

需求原话：「不应该在素材库里面标注，而是在提示词框资产引用那里有两个按钮，可以上传在项目里面的图片」。

- **素材库**：瓦片上的「首帧图/尾帧图」按钮与右键菜单项删除（旧标注仍显示徽标并可点击查看提示；
  后端 `lib_role` 与链级 `chain_head_label/chain_tail_label` 保留，旧项目照常生效）。
- **导演台 · 每段资产引用栏**：新增「＋首帧图」「＋尾帧图」两个按钮 → 弹窗里挑项目内的图片，
  或「＋ 上传一张」（走 `dest=project`，全局库一份 + 项目 assets/ 一份）。
- **段字段**：`segments[i].frame_img = {first, end}`（项目内相对路径，白名单清洗）。
- **执行期生效**（`nodes.py`）：
  - 首段的首帧图 → 提升为 `首帧图片` → i2v 起手帧（官方 I2VA 指令行照旧注入）；
  - 末段的尾帧图 → 提升为 `尾帧图片` → FL2VA 剧情终点锚；
  - 其余段 → 段头/段尾身份锚 keyframe（按文件缓存编码，各文件只编一次）；
  - 段级优先于库内旧标注；换图进逐段哈希（`fimg:`），从该段起重做。
- **关键取舍**：首/尾帧图**不**自动进本段 `refs`。加了 refs 会让首段走 Ref2V（多参）分支，
  反而丢掉 i2v 起手帧语义 —— 锚点是锚点，素材引用是素材引用。

新增测试：`test_repeat_refs_keep_single_token`、`test_parse_frame_imgs`（AST 抽 shipped 纯函数）、
`test_compile_refs_repeat_dedupes_token`、`test_check_segment_refs_repeat_not_over_limit`。

# 第三轮（同日）：提示词框内联绿框 + 锚定方式 + 桌面端输入

## 10. 引用在提示词框里显示成内联绿框

`web/h3_director.js` 新增 `createPromptEditor()`：段提示词框从 `<textarea>` 换成
`contenteditable` 富文本编辑器，`@别名` 渲染成**内联绿框**（`span.h3d-rtag` + `✕` 按钮）。

- 对外暴露 **textarea 兼容接口**（`value` getter/setter、`focus`、`addEventListener`、
  `selectionStart`、`setSelectionRange`、`dataset`、`placeholder`、`dispatchEvent`…），
  所以 @补全、AI 优化、编译预览这些既有代码**零改动**继续可用。
- 绿框是 `contenteditable=false` 的原子节点：光标进不去、退格整块删。
- 序列化：绿框还原成 `@别名`，`<br>`/块级元素还原成换行（有 node 真跑测试）。
- 粘贴只收 `text/plain`（防 HTML 注入）。
- 打字停顿 700ms 自动把裸 `@别名` 收成绿框（IME 组合中不动 DOM，防打断中文输入）。

## 11. 「取消参考清不完」的真正修法：正文 = 唯一真相

之前 refs 与正文是**两份状态**（refs 里 3 条、正文里 2 个 `@标签`，谁对？），所以怎么删都像没删干净。

现在 `syncRefsFromText()` 让 `segments[i].refs` **由正文里的 @别名 序列推导**：

| 动作 | 结果 |
|---|---|
| 点 chip（+1） | 正文插一个绿框 → refs 自动同步 |
| 绿框 `✕` / chip 旁 `✕` | 正文里该素材的**全部**绿框一次清掉 → refs 归零 |
| 手动删正文里的绿框 | 退格即删，refs 跟着掉 |
| 手动打 `@别名` | 700ms 后收成绿框，refs 同步 |
| 清空提示词 | refs 一并清空（此前留着 = 「正文没标签、引用栏还亮着」） |

写入点只有一处：`setPromptText()`（内部调 `syncRefsFromText`），所有编辑路径都经过它。

## 12. 引用语 → 「锚定方式」（先选方式，再点素材）

原交互是"选中一个素材 → 再从下拉里挑句式插到光标处"，顺序反了。现在：

- 下拉变成常驻模式：`锚定方式：无（只插 @标签）` / `主角出场` / `场景还原` / `风格参考` …
  选择按段记住（`_refTpl`），重绘不丢。
- 选中方式后**点参考素材**，该素材就按这个方式写进正文（例：`场景以 @阿依的家 为准，延续其环境、光照与空间布局`）；
  不选 = 只插裸 `@标签`，用法自己在正文里写。
- 每条模板同时带**官方字段语义**：

| 模板 | 官方 retention 标记 | subject_definitions 角色句 |
|---|---|---|
| 主角出场 | fully_preserved | the main subject; keep identity… |
| 配角出场 | fully_preserved | a supporting character… |
| 场景还原 | partially_preserved | the environment reference; keep layout… |
| 风格参考 | weak_reference | a style reference; keep palette… |
| 镜头参考 | weak_reference | a camera-movement reference… |
| 音频参考 | weak_reference | an audio reference… |

**回答「引用语符合官方 skill 格式吗、有用吗」**：句式文本**有用**（`<Picture k>` tag + 语义句
都会进模型），但官方把"怎么锚定"写在**字段**里 —— `subject_definitions`（每个引用是什么角色）
与 `retention_analysis`（`fully_preserved` / `partially_preserved` / `weak_reference`）。
所以模板现在会把角色句与保留标记一起写进**具象化结构**（`prompt_v2.references` / `.retention`），
六字段编译时进官方字段；本段没有 `prompt_v2` 时**不创建**（免得把三字段段悄悄切成六字段），
那时只有句式文本生效。

## 13. ComfyUI 桌面端输入框打不进字（兜底）

桌面端（Electron）偶发：进入后不刷新，所有输入框都打不进字（窗口/画布占着键盘焦点）。
`installDesktopFocusFix()` 三招兜底（正常情况不触发）：

1. 点输入框时若焦点还停在 `body`/`canvas`，主动再 focus 一次（含下一拍重试）；
2. 输入框内的按键在捕获阶段 `stopPropagation`，不被画布热键处理吃掉；
3. 顶栏加「⌨ 输入修复」按钮，手动把焦点抢回来（刷新页面同样有效）。

> 注：这是桌面端宿主的焦点问题，扩展只能兜底；若仍复现，请把「输入修复」按钮与刷新前后的
> 控制台日志一并反馈。

新增测试：`tests/test_prompt_editor.py`（`refsFromText` 与序列化 `ser` 用 node 真跑 + 源码断言）。

# 第四轮（同日）：引用点不动 + 全局库重复一份

## 14. 「资产引用点不了」的三处修法

现象：引用 chip 点了没反应/取消不掉。逐条排查后确认是**三个叠加**的问题：

| 问题 | 原因 | 修法 |
|---|---|---|
| 取消不了 | 上一轮把 chip 改成"点一次=+1"，取消藏在很小的 `✕` 里，且 `✕` 只在**有引用时才显示** → 用户找不到取消入口 | `✕` **常驻**（未引用时置灰）；**右键 chip 也能一键清零**；title 写清"点=+1、✕/右键=清零" |
| 点了像没反应 | `click` 依赖 mousedown/mouseup 配对：卡片重绘可能夹在中间换掉节点 → click 永不到达 | chip / ✕ / 首尾帧按钮全部改 `mousedown`（并 `preventDefault`，编辑器不失焦） |
| 状态闪回 | 防抖中的提示词写回（350ms）可能把刚插入的 `@标签` 覆盖掉 | 新增 `cancelPromptWrite(idx)`：程序化改正文前先丢掉待写队列 |

另外：内联绿框的 `✕` 从 `<button>` 改成 `<span role="button">`（contenteditable 内的
交互元素在 Chromium 下 click 有时被选区逻辑吃掉），并给所有引用操作加了 try/catch ——
失败不再静默（写 LED + 控制台）。

## 15. 全局库"多出一份"：上传落点改为纯净 + 调入项目改为链接

**上传**（`library_upload`）：以前"项目落点也往全局库复制一份"，用户明确反馈不对。
现在**上传到哪里就是哪里**：

| scope | 落点 | 说明 |
|---|---|---|
| 全局库 | 只进全局库 | 跨项目复用 |
| 项目资产 | 只落 `<proj>/assets/` + 登记清单 | 新增 `library.store_to_project()`，**不碰全局库** |
| 成片 | 只落 `<proj>/finals/` | 目录扫描即见 |

想要"全局库也存一份"= 项目瓦片上的 **「存入全局库」** 显式动作（复用 `/h3chain/lib_archive`）。

**调入项目**（`lib_mirror`）默认从"复制文件"改为 **`mode="link"` 链接引用**（只写
`manifest.asset_links`，文件仍只在全局库一份）—— 这正是双层存储的原意（一次入库、
多项目链接、不复制）。同时：

- 「项目资产」视图现在**会列出链接条目**（`library._link_entries`，带「🔗 链接」徽标），
  否则点完调入项目看不到东西，会以为没生效；
- 链接条目的绝对路径按**全局库**解析（缩略图/预览不再 404）；
- 删除链接条目 = **解链**（`lib_delete` 里分流），绝不删全局库那份文件；
- 仍保留「调入项目（复制一份到项目 assets/）」菜单项，给"项目要自包含"的场景。

测试：`test_upload_dest_project_stays_in_project`（断言全局库不新增）、
`test_mirror_link_not_copy`（链接不复制文件）、`test_link_entries_listed_and_resolved`。

# 第五轮（同日）：`引用操作失败：reading 'length'` 的真凶

用户报错：`引用操作失败：Cannot read properties of undefined (reading 'length')`。
用 **node + jsdom 抽 shipped 源码真跑**复现（`tests/js/prompt_editor_check.js`），
一次抓到两个真 bug —— 都在 `createPromptEditor` 内部：

## 16. `box.value` —— div 没有 value

`box` 是 `<div contenteditable>`，**没有 `.value`**；正文只能经 `ser(box)`（或兼容面
`api.value`）拿。我在 `insertTag` / `removeTag` / `tagCount` 里写成了 `box.value`：

| 函数 | 后果 |
|---|---|
| `insertTag` | `cur = undefined` → `cur.length` 抛错 → **chip 点了报错**（用户看到的那条） |
| `removeTag` | `re.test(undefined)` 恒为 false → **静默 return false** → ✕ 取消不掉（"清不完"） |
| `tagCount` | `undefined.match` 抛错 |

修法：三处改 `ser(box)`；`set value` 里 `box.value.length` 一并改掉。
并加注释写明「box 没有 .value」这个坑。

## 17. `focus()` 未定义 + 删除短标签误伤长标签

- `insertTag`/`removeTag`/`insertText` 里写了裸 `focus()`（编辑器作用域内没有这个函数）
  → `ReferenceError: focus is not defined`。改 `box.focus()`，并且**先 focus 再摆光标**
  （focus 会把 contenteditable 的光标重置到开头，顺序反了会插到文首）。
- 删除/计数原用正则 `@标签(?![0-9A-Za-z_])`：负向后顾只挡 ASCII，中文挡不住 →
  删「阿依」会把「@阿依的家」的前缀一起吃掉（剩「的家」）。改成**最长优先分词**
  `refTokens()`，渲染/计数/删除共用一条路（与后端 `compile_refs` 同口径）。

## 18. 回归闸

新增 `tests/js/prompt_editor_check.js`（node + jsdom，抽 shipped 源码真跑 8 组断言：
插入不抛错、句式插入、重复计数、短标签不误伤长标签、落盘同步 refs、chip 链路、
✕ 清零、`refsFromText` 邮箱不误伤/最长优先），由
`tests/test_prompt_editor.py::test_editor_runtime_jsdom` 调用（缺 jsdom 自动跳过）。
`escapeRegExp` 随之删除（不再有正则式引用匹配）。

# 第六轮（2026-09-13）：引用监控"更新不及时" + 「裸引用/无」重复档

用户报三件事：① 切了锚定方式后，第二个素材的绿框"来不及出现"，再点一个素材
才出来；② 在提示词框里按绿框的 ✕，引用条状态不更新，要再点别的才更新；
③ 「裸引用」和「无」不是一个意思，为什么有两个选项。

## 19. 根因：焦点守卫把"整卡重建"整条路都掐了，而卡片内状态只有这一条刷新路

`renderCenterColumn` 的 `locked` 守卫（常驻编辑器聚焦 / v2 输入聚焦 / 播放 / 拖拽）
会**整体跳过**重建——这是为了不丢焦点不丢草稿，本身是对的。问题是卡片内的即时状态
（引用 chips 的 ✓/＋/×N、计数文案、正文绿框）**只靠整卡重建刷新**，于是：

| 动作 | 谁负责刷新 | 实际结果 |
|---|---|---|
| 点 chip | chip 处理器里 `paintAll()` | ✅ 即时 |
| 点绿框 ✕ | `onRemove` → `applyPromptEdit` + `scheduleRefresh(240)` | ❌ 刷新被 locked 丢掉 → **chips 停在旧值**，再点别的 chip 时它的 `paintAll()` 才把全部 chips 纠正过来（"再按别的才更新"） |
| 切锚定方式 | `tpl.onchange` → `paintAll()` | ✅ chips ✅，但正文绿框不重渲 |
| 素材晚到（上传/外部写入） | 只靠整卡重建 | ❌ 快照旧 → @别名 一直是裸文本；chip 也一直是旧的 |

## 20. 修法 A：卡片注册"轻量重绘"钩子，锁定期间照常推进卡片内状态

- 新增 `_cardPainters` / `registerCardPainter()`（`buildCards` 每次重置；
  `renderCenterColumn` 在 `locked` 分支里逐个调用，单卡抛错不影响别的卡）。
- 每张段卡注册一个 `repaintCard()`：**先补绿框 → 再重画 chips + 计数 + 首尾帧按钮**。
- `repaintCard()` 同时是 ✕ / chip / chip-✕ 的即时刷新入口（不再等 240ms 刷新）。
- 守卫 `if (!ta.el || !ta.el.isConnected) return;`：卡片已被换掉时不许拿旧 DOM 回写状态。

## 21. 修法 B：别名表与素材池改读**活**状态（不再读建卡快照）

`collectData()` 产出的 `data.ds` 是**快照**，建卡后上传/改名/删素材都不会变它，
而卡片在聚焦期间又不会重建 → 快照能一直停在建卡那一刻。

- 编辑器 `labels`：优先 `getDs(node).ref_assets`，快照只作回落。
- 引用条：`livePool()` + `syncChips()` —— 池的别名序列变了就整批重建 chips
  （`mkChip()` 抽成独立构造函数，插入点在计数前面，顺序稳定）。
- `createPromptEditor` 新增并暴露 `normalizeLoose()`：把正文里"还没成框"的 @别名
  就地渲染成绿框，幂等（无裸别名时返回 false 不动 DOM，因此不会被 900ms 轮询打扰）；
  补框成功后立刻 `applyPromptEdit()` 回写正文与 refs，chips 随即变 ✓。
  原来这段逻辑只在 `input` 后 700ms 跑一次，且用的是旧别名表 → 补不上。

## 22. 「锚定方式：无」与「裸引用（不加描述）」合并

两档插入的正文**逐字节相同**（都是裸 `@标签`），却在同一个下拉里并列，纯属重复：

- 删掉 `mkOpt("", "锚定方式：无（只插 @标签）")`；`REF_TPL_DEFAULT = 0`（裸引用）成为
  默认档，`_refTpl` 取值域由 `-1|下标` 收成 `下标`。
- 语义差异保留在**具象化结构**里：裸引用仍带 `partially_preserved` 保留标记
  （`applyRefAnchorToV2`），只是不再有"什么都不写"的第二档来搅浑水。

  即时补框且幂等；绿框 ✕ 同步回调 `onRemove`（引用条据此即时归零）；裸引用模板为第 0 档。

# 第七轮（同日）：绿框 ✕ 应该是"取消这一处"，不是"清光同名全部"

上一轮把绿框自带的 ✕ 接到了 `removeTag(label)` —— 那是**清全部**的历史语义
（引用条 chip 旁的 ✕ 就该是这个）。于是同一素材引用多次时，点一个绿框的 ✕ 会把
正文里所有同名绿框一起清掉；而且 `onRemove` 里还跟了一句 `removeSegmentRef`，
一次点击会让引用计数掉 2。用户报："点小叉就全叉掉了，不应该是只叉一个吗"。

## 24. 两层 ✕ 语义分层

| 入口 | 语义 | 实现 |
|---|---|---|
| 正文里绿框自带的 ✕ | 只取消**这一处**（引用 N 次点 N 下，一次少一处） | `removeOneTag(tagEl)` |
| 引用条 chip 旁的 ✕ / 右键 chip | 取消本段对它的**全部**引用 | `removeTag(label)`（不变） |

`removeOneTag(tagEl)` 的做法：正文（序列化文本）是唯一真相，所有渲染都由
`render(文本)` 重建，所以不能直接删 DOM 节点，只能把**文本里第 nth 个同名 token**
去掉。nth 由"被点的绿框在同名绿框里的序号"推出来 —— 绿框顺序与 `refTokens` 顺序
一致（都是 render 产物），所以两者一一对应。计数、置灰全自动跟上：
`refs` 由正文重算 → 引用条 `paintAll()` 把 chips 从 ×N 变 ×(N-1)，降到 0 时
chip 丢掉 `.on` 变灰、旁挂 ✕ 加 `.off`。

## 25. 顺手修掉的双减

`onRemove` 里 `applyPromptEdit` 之后原本无条件跟一句 `removeSegmentRef(node, it.idx, label)`。
在"清全部"时代这是双保险（正文已无该标签 → refs 已归零 → 再减是空操作）；
但 ✕ 改成只清一处后，正文重算出的 refs 还剩 N-1，再减一次就变成 N-2
——**引用 2 次点一下直接归零**。现在只在写回失败时兜底：

```js
if (!applyPromptEdit(node, it.idx, ta)) removeSegmentRef(node, it.idx, label);
```

## 26. 附带一致性调整

- `tidy()` 抽成函数（`removeTag` / `removeOneTag` 共用），并**补上结尾空白清理**
  （原来只清行首，删掉一个尾部绿框会留下尾随空格）。
- 两处 tooltip 明确分层：绿框 `title` 写「只取消这一处引用」，
  引用条 chip 的 ✕ 写「取消本段对它的全部引用」，互相点名对方在哪。
- 测试：`prompt_editor_check.js` 增 ⑫（点一次只掉一处：tagCount 2→1→0、
  `applyPromptEdit` 后 refs 只剩 1）与 ⑬（`removeOneTag` vs `removeTag` 语义不能混）；
  `test_prompt_editor.py` 增 `test_two_level_remove_semantics()`（绿框 ✕ 必须调
  `removeOneTag`、chip ✕ 调 `removeTag`、`removeSegmentRef` 全文只出现一次且带条件）。
- `H3D_VER` → `20260913+ref-remove-one`。

# 第八轮（同日）：素材库"库间动作"收口 —— 删「全部」、删链接形态、成片补按钮

用户反馈：全局库里「调入项目」生成一条**链接**太诡异（项目里多了个条目，文件其实还在
全局库），而且旁边还挂一个「复制进项目」，两个按钮谁是谁说不清；另外素材库顶上的
「全部」这一栏纯属多此一举。

## 27. 库间动作只剩"复制 / 存入"两种，且每个方向只有一个按钮

| scope | 瓦片按钮 | 语义 |
|---|---|---|
| 全局库 | **调入项目** | `lib_mirror(mode="copy")`：复制一份进 `<proj>/assets/` 并登记清单（唯一形态） |
| 项目资产 | **存入全局库** | `lib_archive`：全局库多一份，跨项目复用（不变） |
| 成片 | **调入项目** + **存入全局库** | 调入 = `move_media` 从 finals/ 挪进 assets/（搬家，提示里写明了）；存入全局库 = 新增按钮 |
| latent | 二采 / 改名 / 删除 | 无库间动作（全局库不收 latent） |

- 删掉「复制进项目」按钮与右键里的两个「调入项目（链接 / 复制）」选项；
  `actMirrorCopy` → `actBring`，固定 `mode="copy"`。
- 后端 `lib_mirror` 的 `link` 分支**保留**：老项目里已有的 `asset_links` 条目仍要能
  显示（带「🔗 链接」徽标）、能解链（`lib_delete` 分流），只是前端不再新建。
- 多选右键新增「⬆ 把选中的 N 个存入全局库」（`actArchiveMany`），并过滤掉 latent
  （全局库只收 image/video/audio，否则后端逐个 KeyError）。

## 28. 删掉「全部」子面板

`SCOPES` 去掉 `["all","全部"]`（后端 `library.SCOPES` 本来就没有 all），默认停在
**项目资产**。理由：四个库的文件位置语义不同，混一栏看不出东西到底在哪；而且上传落点
是按当前 scope 决定的，「全部」会让落点含糊。计数徽标改为每个 scope 都显示。

## 29. 成片不再"打开就自动存一份进全局库"

删掉 `autoArchiveFinals()`：静默复制正是"诡异"的来源，入库改成瓦片上的显式按钮；
顺带省掉每次打开成片都要给大视频算一遍 sha256（`register_content` 是内容寻址）。

> 副作用：成片入库从"自动"变成"手动"。想要自动备份可在成片生成后自行点一次
> 「存入全局库」，或把 `autoArchiveFinals` 加回来（幂等，`register_content` 同 sha 秒传）。

- 测试：`tests/test_frontend_p3.py::test_library_browser_ui` 仍全绿（45 passed）。
- `H3D_VER` → `20260913+lib-scope-actions`。

# 第九轮（次日）：库间调入加"目标库同名"闸门 —— 有同名就不显示调入按钮

用户接着要求：不管哪个方向（调入项目 / 存入全局库 / 成片调入），**目标库里已经有同名文件
时，这个方向的按钮干脆不出现**；而且调入一次之后按钮要立刻自动消失。

## 30. 判定必须在后端做

前端只有当前页（60 条），看不到目标库全貌 —— 自己比对会漏。所以：

- `library.name_keys(item)`：判定"同名"的键集 = **显示名 + 文件名**，统一
  `去扩展名 + 小写`，再补一个 **24 字截断**键。
  - 全局库存的是内容寻址文件名（`ab12cd34_阿依.png`），显示名才是 `阿依.png`；
  - 项目资产的显示名被 `apply_aliases` 覆盖成 manifest 别名 `阿依`（**无扩展名**）；
  - `manifest.assets[].label` / `asset_links[].alias` 入库时被截到 24 字，超长名字
    截断后才是真正写进项目的名字 —— 不补这个键就会漏判、让人连点两次复制出两份。
- `library.MOVE_TARGETS`：每个 scope 允许调入的目标 scope（**只列跨库方向**，
  同库内本来就可以有同名，不参与判定）。
- `library.blocked_targets(items)` → `{item_id: [目标 scope...]}`，两种命中：
  1. **同名**：`name_keys` 与目标库任意条目相交；
  2. **已链接**（仅 全局库 → 项目）：项目 `asset_links` 里已有同一 `asset_id`，
     那就已经在项目里了，不该再复制一份（不靠名字，靠 asset_id）。
- `routes.lib_list` 用**完整索引**算好，把 `blocked` 挂到返回的每条 item 上。

## 31. 前端只认 `it.blocked`

- `isBlocked(it, target)`：命中就不画这个方向的按钮（瓦片 + 右键菜单），
  多选批量动作也按同一套判定过滤（否则一次点下去照样复制出重名）。
- 被挡掉时瓦片挂一个**说明徽标**（虚线灰字「同名已在项目资产」+ tooltip）——
  不是按钮，只是解释"为什么没有按钮"，免得用户以为功能坏了。
- 动作完成后 `fetchPage(false)` 重拉 → 按钮自动消失。前提是索引缓存要失效：
  补了 `move_media` 路由的 `h3lib.invalidate()`，并把 `lib_archive` 的失效从
  「只有真入库才失效」改成**每次都失效**。

## 32. 接口层兜底（防绕过界面直接打接口）

- `lib_mirror(mode="copy")`：项目已有同名 → **409 `DUP_NAME`**，不复制第二份。
- `lib_archive`：全局库已有同名 → 跳过，进 `skipped`（注明「全局库已有同名」）。
- 注：成片 → 项目走的是通用 `move_media`（同名自动加 `_2`），那个端点也被
  剪辑面板的「库间互调」复用，所以只在**前端**挡，后端保持原行为。
