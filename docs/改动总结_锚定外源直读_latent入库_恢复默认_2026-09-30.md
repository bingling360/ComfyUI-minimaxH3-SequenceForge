日期：2026-09-30　分支：`anchor-studio2`

本轮五件事都来自用户同一天的实际使用反馈。

---

## 1. 生成视频作锚源不再误报「没有别名」

**症状**：把生成出来的视频（成片 / 分段 mp4，落在「成片」库）放进手动锚定，
面板立刻警告「没有别名、也没有 asset_id，生成时节点侧寻址不到」。

**根因**：成片 scope 是纯目录扫描（`library.scan_scope("finals")`），条目
`asset_id` 恒为空；`routes._anchor_ref_of` 对它回落到**裸文件名**当 ref——执行期
`nodes._anchor_asset` 只认「标签池 / 注册表 asset_id」，裸文件名两头都不在，
必报「未知素材标签」。面板的 `resolvable` 提前如实说了这件事，但结论是"这个素材
没法用"——而它明明就在项目里。

**修法**：给成片条目一条**直读寻址**通路，ref 改成项目相对路径：

- `routes._anchor_ref_of`：成片条目 ref = `file`（如 `finals/seg_003.mp4`）；
  全局库 latent 条目 ref = asset_id。
- `nodes._anchor_asset`：新增第一级寻址——`finals/videos/merges/clips` 前缀 +
  每段防穿越检查 + 文件存在 → 直接返回绝对路径（扩展名→kind 与 want_kind 比对）。
- `nodes._load_library_latent`：ref 不是 `latent/<名>.pt` 时按 **asset_id / 别名**
  从注册表解析到全局库里的 `.pt`——这是"旧项目 latent 衔接新项目"的执行期通路。
- `routes anchor_sources` 的 `resolvable` 口径与执行期逐字对齐：成片相对路径、
  项目 latent 文件存在都算可寻址。挑 latent 也不再误报（此前 latent 库条目
  同样被误判）。

> 迁移说明：旧存档里用裸文件名 ref 的成片锚本来就不能执行，面板现在会提示
> 「源已不在素材库里」，重选一次即换成新 ref。

## 2. latent 上传渠道 + 调入全局库

此前 latent 库**没有任何上传入口**（上传白名单没有 .pt，前端按 MIME 猜类别
必然猜成 image），也**不能**「存入全局库」（`MOVE_TARGETS["latent"]=()`，
asset_store 也不收 latent kind）。跨项目衔接 latent 只能手工拷文件。

- `asset_store.py`：`KINDS` 收 `latent`；`register_content` 落库内 `latents/`；
  `_MEDIA_EXT` 收 latent 容器后缀（别名剥 `.pt` 与图片同语义）。
- `projects.register_latent_file`：外部 `.pt` 拷进项目 `latent/`（同名加 _2）
  并登记 `manifest["latents"]`——与 slice_latent 产物同构。
- `routes.library_upload`：白名单加 `latent: ("pt",)`（**只收 .pt**——执行期
  `torch.load` 只认 `{"video":...}` 容器，放行 .safetensors 会造出"能列出、
  当锚源必炸"的死条目）；`_upload_kind` 按扩展名把误判成 image 的 .pt 改判；
  `dest=project` 且 `kind=latent` 落 latent 库；成片库拒收 latent。
- `library.MOVE_TARGETS`：`latent -> ("global",)`——存入全局库成为跨项目复用正路。
- 前端 `h3_assets.guessKind` 按扩展名认 `.pt`；`h3_library` 上传按钮文案
  （latent 库页签显示「上传到 latent 库」）、右键菜单与批量「存入全局库」
  放开 latent。

**跨项目衔接的完整链路**：旧项目 latent 库 →「存入全局库」→ 新项目锚定面板
「选素材」挑它 → ref=asset_id → 执行期注册表解析回全局库 `.pt`。

## 3. 素材库瓦片「⬇ 下载」常驻按钮

下载原来只藏在右键菜单和预览器侧栏，瓦片上没有。现在每张瓦片都有
「⬇ 下载」（`tileButtons`），走既有 `lib_raw?download=1` 通路。

## 4. 手动锚定默认值（2026-09-30 拍板）

- **取用窗默认贴源结尾**：新增 `tailStart(frames, win)` 统一算法，
  `newAnchor` / 上段对齐 / 挑素材三条路径都落它——衔接用的是"最近发生的那几帧"。
- **来源默认**：有上一段 → 「上段」并预填；没有上一段（第 1 段）→ 「素材」。
  本面板最核心的两个用途（外部视频/latent 给初始段参考、旧项目 latent 衔接）
  都从素材库进来，在没有上段的段上默认「上段」只会得到一条必改的死锚。
- **「段」更名「上段」**：段源说的就是上一段，单叫「段」让人以为是任选段落。
- 「生成预览」按钮只对项目内 `latent/<名>.pt` 显示（全局库 latent 没有
  "同段 finals 视频"可抽帧，`anchor_sheet_build` 也不认 asset_id，不摆必败按钮）。

## 5. 恢复默认设置按钮（三处）

| 位置 | 机制 |
|---|---|
| ⚡ 性能优化弹窗底栏 | POST 空 `perf` 对象——`perf.parse_state` 以 `DEFAULT_PERF` 起底，空对象解析出来就是完整默认副本；成功后关掉重开面板按默认值重建 |
| 导演台右栏三区（链参数 / 语义桥 / 二采） | 各区右上角「↺ 恢复默认」。链参数用 `CHAIN_DEFAULTS`（nodes.py INPUT_TYPES default 的前端镜像）逐控件写回；语义桥 / 二采直接 `defaultBridge()` / `defaultUpscale()` 整份覆盖 |
| ⚙ AI 优化设置弹窗底栏 | `optDefaultSettings()` 整份覆盖 `ds.optimizer`（Key 一并清空；服务端内置 Key 仍兜底，开箱可用不受影响） |

全部带 confirm 确认；恢复后局部重渲（`repaintParams` / `repaintUpscale` /
`repaintBridge`），不整页重刷。
