# 改动总结：「音频VAE」改为可选（无音频模式，2026-10-17）

来源：用户要求「VAE 在导演台主节点不应该是必须输入 —— 比如想做视频迁移又不想要音频，
音频 VAE 就完全没必要输入」。

改法：`H3SeamlessChainSampler` 的 `音频VAE` 由**必填**改为 **optional**。不接 = **无音频模式**：
全链按静音处理。采样本身一字不改（模型仍然产出官方 AV latent 的两个分支，音频分支照常跑、
照常落存档），只是**不编码、不解码**音频——没有音频 VAE 就没有可解码的东西。

`视频VAE` 仍是必填：任何链路都要解码画面，放开它只会把报错从"槽没接"挪到运行时，没有收益。

## 二、无音频模式的行为表

| 环节 | 行为 | 理由 |
|---|---|---|
| 采样 | ✅ 照常（AV latent 双分支都在） | 官方节点/采样器要求嵌套 latent 两分支同时在场，缺音频分支会崩；保持形状不变最省事也最安全 |
| 参考音频 `<Audio j>` | ✅ 仍进**文本编码器**参与画面描述 | 与官方 `MiniMaxH3ReferenceToVideo` 同口径："Without it reference audio only conditions the text encoder." 只是不再走音频 latent 分支 |
| 段/成片 mp4 | 等长**静音** AAC 轨（32 kHz） | 零波形而不是 0 样本空轨：下游播放器/合并逻辑拿得到时长基准，混拼时 PyAV 重采样支路零开销直通 |
| 序章 `起始视频音轨` | ⚠ **忽略**并写进报告 | 没有 VAE 就没法编码；静默丢掉属于"设了不生效还不说"，必须报 |
| 锚点取用分支 `仅音频` / `图像+音频` | ❌ **硬报错**并点名锚 id | 手动锚不静默降级（项目红线）；改「仅图像」或接上音频 VAE 二选一 |
| 音频 latent 落存档/回放 | ✅ 照常（零张量） | 二采 `upscale` 与重摇都要读它，`audio_t.to(...)` 不允许 None |
| 响度对齐 / 接缝 dB | 自动跳过（RMS≈0 判据已存在） | `qc.loudness_align_head` 里 `ra<1e-6 or rb<1e-6` 直接返回 None，无需改动 |

**采样率为什么取 32000**：H3 音频 VAE 的输出就是 32 kHz（`comfy/ldm/minimax/audio_vae.py`：
`sample_rate = output_sample_rate = 32000`；40 latent token/s × 800 hop = 32000 样本/s，与
`grid.FRAME_RESCALE = 5/3 @24fps` 自洽）。静音占位取同一个值，静音段与真音频段混拼时不用重采样；
即使跨运行混了不同率，`media.concat_av_mp4` 也会按首个含音轨源统一重采样。

## 三、守卫设计（别被后面的改动绕过）

1. **`无音频 = audio_vae is None` 只写一处**，下游一律问 `_audio_dev()`（未接时随视频 VAE）。
   测试钉住 `audio_vae.device` 在 `nodes.py` 里出现且只出现一次。
2. 所有"拿 audio_vae 干活"的调用点（`_encode_audio_latent(audio_vae` / `_decode_audio(audio_vae`）
   附近必须有 `无音频` 守卫，测试回看 5 行窗口逐个点名。漏一处 = 无音频模式第一次跑到那儿
   就是 `AttributeError: 'NoneType' object has no attribute ...`。
3. 显式意图（序章音轨、锚点音频分支）**要么报错、要么写报告**，绝不静默降级。
