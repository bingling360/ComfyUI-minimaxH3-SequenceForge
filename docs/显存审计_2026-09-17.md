## 1. ComfyUI 官方到底怎么管显存（事实 + 行号）

### 1.1 五档 VRAM 状态与默认

`comfy/model_management.py:45-59`

```
DISABLED=0 / NO_VRAM=1 / LOW_VRAM=2 / NORMAL_VRAM=3 / HIGH_VRAM=4 / SHARED=5
默认 vram_state = NORMAL_VRAM
```

`--highvram / --lowvram / --novram / --gpu-only / --cpu` 互斥改这个状态（`cli_args.py:167-172`）。
**项目从来不设这些参数，所以跑在 NORMAL_VRAM。**

### 1.2 DynamicVRAM = comfy-aimdo（官方默认开，不是第三方魔改）

- `comfy/memory_management.py:173` —— `aimdo_enabled = False`（初值）
- `main.py:273-302` —— 开启条件：
  ```
  if args.enable_dynamic_vram or (enables_dynamic_vram() and dynamic_vram_supported()):
      aimdo_initialized = comfy_aimdo.control.init_devices(...)
      if aimdo_initialized:
          comfy.model_patcher.CoreModelPatcher = ModelPatcherDynamic
          comfy.memory_management.aimdo_enabled = True
  ```
- `cli_args.py:317-320` —— `enables_dynamic_vram()` = 非 `--disable-dynamic-vram` 且非
  highvram/gpu_only/novram/cpu → **默认 True**
- `cli_args.py:264-270` —— `dynamic_vram_supported()` = NVIDIA 全支持；AMD 需 ROCm ≥7.14
- `comfy-aimdo==0.5.5` 在官方 `requirements.txt` 里是**硬依赖**（本机装的是 0.5.3）

**所以：现代 ComfyUI + N 卡 = DynamicVRAM 默认接管权重，权重按需从磁盘 mmap 分页到 GPU。**
`ModelPatcherDynamic` 用 VBAR 预留 `model_size × 10` 的虚拟地址空间（`model_patcher.py:1809`），
把显存当权重缓存**故意填满** → "空闲显存接近 0" 是设计使然，不是异常。

### 1.3 两个"空闲显存"口径（关键，项目踩在这里）

| 函数 | 含义 | 位置 |
|------|------|------|
| `mm.get_free_memory(dev)` | `torch.cuda.mem_get_info` 的 free **+** torch 分配器里的空闲缓存块 | `model_management.py:1779-1823` |
| `patcher.get_free_memory(dev)` | 上面那个 **+** aimdo 可换出的权重（`vbars_analyze`） | `model_patcher.py:417-425` |

`model_patcher.py` 的注释写得很直白：
> Prioritize batching (incl. CFG/conds etc) over keeping the model resident...
> return everything both torch and Aimdo could give us

**结论：DynamicVRAM 下要问"还剩多少可用"，必须用 `patcher.get_free_memory()`。**

### 1.4 卸载 / 加载的实际行为

- `unload_all_models()`（`model_management.py:2112`）= 对每个设备 `free_memory(1e30, device)`
  - 注意它 **没有**传 `for_dynamic=True`，所以走的是非 dynamic 分支
    （`model_management.py:914-919` 的 `for_dynamic` 判断不成立）
  - → `LoadedModel.model_unload()`（`:835`）→ `partially_unload` → 对 dynamic patcher
    是 `vbar.free_memory(memory_to_free)` + `restore_loaded_backups()`（`model_patcher.py:2043-2068`）
  - **所以 `unload_all_models()` 在 DynamicVRAM 下确实能腾出显存**（换出权重页），项目这么用是对的
- `soft_empty_cache()`（`model_management.py:2094`）= `synchronize + empty_cache + ipc_collect`，
  **不卸载任何模型**，只清分配器缓存
- 采样前加载：`sampler_helpers.py:201`
  ```
  load_models_gpu([model] + models, memory_required=..., minimum_memory_required=...)
  ```
  `models` 只含 cond 里的附加模型 → **unload_all_models 后采样只回载 UNET**（项目注释的说法成立）
- `memory_required` 的估算（`model_base.py:417-439`）：
  ```
  area = batch(CFG→×2) * prod(T,H,W)          # 注意不含 C
  flash/xformers: area * dtype_size * 0.01 * memory_usage_factor * 1MB
  否则:           area * 0.15 * memory_usage_factor * 1MB
  ```
- VRAM 分配上限：`maximum_vram_for_weights = total*0.88 - minimum_inference_memory()`，
  `minimum_inference_memory = 0.8GB + EXTRA_RESERVED_VRAM`（`:890-1134`）

### 1.5 VAE 解码（项目高清解码走这里）

`comfy/sd.py:1232-1311`：
```
memory_used = self.memory_used_decode(shape, vae_dtype)
load_models_gpu([self.patcher], memory_required=memory_used)
free_memory = self.patcher.get_free_memory(self.device)     # ← 用含 aimdo 的口径
batch_number = max(1, int(free_memory / memory_used))        # 显存不够就分批
...
except: → OOM 自动降级 tiled（:1269 打 warning）
        3D 路径还会按预算反推 tile_t / tile（:1297-1308）
```
**即：解码前 GPU 上还压着 26GB UNET 时，`batch_number` 会退化、或直接 OOM 转 tiled 3D。**
tiled 能出片但慢，且 `decode_tiled_3d` 的 overlap=(1,8,8) 有额外计算。

### 1.6 其它值得知道的事实

- `intermediate_device()`（`:1265`）：**无 `--gpu-only` 时恒返回 CPU** —— 项目把它当"放大网络默认设备"
- `unet_inital_load_device`（`:1112`）：`aimdo_enabled` 时**恒返回 CPU**（权重先落 CPU 再分页）
- `text_encoder_device()`（`:1219`）：NORMAL_VRAM 且 fp16 可用才上 GPU
- attention 后端：`xformers / flash / sage / pytorch`，影响激活峰值
- `comfy.utils.tiled_scale_multidim` 的 `output_device` 支持边解码边落 CPU 输出

## 3. 问题详解

### P0-1 / P0-2：放大前向在 autograd 下跑（最大的单项）

`upscale.py:698-708`：
```python
x  = video_t.detach().to(net_dev, torch.float32)
xn = (x.to(nd) - mean) / std
y  = net(xn, scale=..., target_size=...)      # ← 没有 with torch.no_grad():
return y.to(torch.float32) * std32 + mean32
```
- 输入 `detach()` 了，但**网络参数 `requires_grad=True` 未关**（`upscale_net.py:880` 只有 `.eval()`），
  所以输出 `requires_grad=True`，PyTorch 会为整条前向建图并保存每层激活
- 分块循环里 `out_full[:, :, ...] += valid_out * weight`（`upscale_net.py:439`）也会把
  grad_fn 带进 `out_full`，整条图活到函数返回
- **上游快照里有，迁移时丢了**：
  - `docs/upstream_snapshot/2026-09-02/minimax_h3_latent_upscaler_3d.py:440`
    `model = model.to(device).eval().requires_grad_(False)`
  - 同文件 `:584` `with torch.inference_mode():`
- 全项目 grep `no_grad` 只在 `metrics.py:163`、`optimizer.py:481` 有 —— 二采路径一处都没有
- 影响：3D 网络 24 个残差块 × 512 通道 × 32 帧块，激活被逐块钉住不释放；
  这也能解释"每 4 块 `gc.collect()`"这种补丁式写法为什么会被加进去

**修法（两行）**：`upscale_net.load_model` 末尾加 `requires_grad_(False)`（含缓存命中分支），
`upscale_video` 的 `net(...)` 包 `with torch.inference_mode():`。
`inference_mode` 比 `no_grad` 更省（连版本计数器都不维护），且输出直接 `requires_grad=False`。

### P0-3：`_dynamic_vram_active()` 检测的是错的东西

```python
# upscale.py:1014-1021
if any("aimdo" in k for k in sys.modules): return True
return importlib.util.find_spec("aimdo") is not None
```
- `comfy_aimdo` 是官方**硬依赖**，`comfy/memory_management.py:7` 就 `import comfy_aimdo.host_buffer`
- 而 `render_latent:1313` 第一行就 `import comfy.model_management` → 必然拉起 `comfy_aimdo`
- → **只要 ComfyUI 版本够新，这个检测恒为 True**，跟 DynamicVRAM 是否真的接管权重无关
- 后果：`preflight` 的显存不足**永远只报 ⚠ 不硬停**（`:1132-1135`），硬停分支成了死代码；
  反过来，在**真·老环境/关了 DynamicVRAM** 的机器上，它又可能因为没装 aimdo 而误判 False

**修法**：直接读真开关
```python
import comfy.memory_management as _cmm
return bool(getattr(_cmm, "aimdo_enabled", False))
```

### P1-1：`_vram_gb()` 口径偏小

```python
# upscale.py:865
return mm.get_free_memory() / (1024 ** 3)
```
DynamicVRAM 下 aimdo 占的权重缓存不计入，量到的"空闲"接近 0 → 预检账目严重悲观
（配合 P0-3 就变成"永远紧张、永远只警告"）。

**修法**：`_vram_gb()` 优先取 `模型.patcher.get_free_memory(device)`，退回 `mm.get_free_memory()`。
`_reclaimable_gb()` 同理可改用 `lm.model.loaded_size()`（dynamic 下含 vbar 实际驻留）。

### P1-2：高清解码前不卸 UNET

`upscale.py:1795` 紧接精化之后调 `video_vae.decode(up_v)`，此时 UNET 刚被回载在 GPU 上。
官方 `sd.py:1245` 的 `batch_number = free_memory / memory_used` 会退化到 1，
`memory_used_decode` 对 H3 类 VAE 是 `2800 * T * H * W * 64 * dtype_size` 量级（`sd.py:796` 一类公式），
基本必 OOM → 进 tiled 3D 降级（`:1289-1308`），能出片但慢且多一遍 overlap 计算。

**修法**：解码前 `comfy.model_management.unload_all_models()`（或
`unload_model_and_clones(模型)`，只卸 UNET 保留 VAE），再 `decode`。
代价：下段一采要重新回载 UNET，与现有 `_up_swap` 分支同性质（`nodes.py:2353-2372` 已经在付这个代价）。

### P2-1：预检用经验系数，口径与运行时不一致

```python
_ACTIVATION_FACTOR = 4.0   # upscale.py:1006
need = latent_gb * 4.0 + 1.0
```
而运行时真正决定 "ComfyUI 会为这次采样预留多少" 的是
`sampler_helpers.estimate_memory()` → `BaseModel.memory_required()`（`model_base.py:417-439`），
它以 `batch × T × H × W`（不含 C）× dtype × 0.01 × factor 计算，并区分
xformers/flash 与否 —— 与 `latent_gb × 4` 完全不是一回事。

**修法**：预检直接复用官方口径，账目和运行时的行为才对得上：
```python
from comfy.sampler_helpers import estimate_memory
need, need_min = estimate_memory(模型, noise_shape, conds)   # 需要构造 cond，或至少
need = 模型.model.memory_required([2, C, T, h2, w2])          # 退一步只要这一行
```
（`ModelPatcherDynamic.memory_required` 已经额外 ×1.3 +1GB，`model_patcher.py:1840-1844`）

### P2-2：高清帧全序列驻留 GPU

`upscale.py:1795-1818`：解码 → 裁剪 `skip_f:skip_f+vis_len` → `pixel_sharpen_frames`（内部逐块 `.to("cpu")`）→
`save_segment_mp4` → `save_thumb`。整段高清帧（N×H×W×3 fp32）在 GPU 上活到函数返回。
`pixel_sharpen` 已经证明"逐块 CPU 处理"可行，**解码后立刻按块落 CPU** 就能把这块峰值压掉。
（也可直接用官方 `decode_tiled_*(output_device=cpu)`。）

### P3-1：`MODEL_CACHE` 只增不减

`upscale_net.py:482`，`force_unload` 默认关。CPU 侧权重副本长期驻留（主要吃 RAM 不是显存），
多段链后段 RAM 紧张时才明显。已有开关，优先级低。

## 4. 建议动手顺序

1. **P0-1 + P0-2**（两行改动，收益最大、风险最低）：`requires_grad_(False)` + `inference_mode`
2. **P0-3**：`aimdo_enabled` 直接读真开关，让预检恢复它该有的硬停能力
3. **P1-1**：`_vram_gb` 改 `patcher.get_free_memory`，账目才可信
4. 加一段**显存实测埋点**（见 §5），先量化 1-3 的真实收益再继续
5. **P1-2**：解码前卸 UNET
6. **P2-1 / P2-2**：口径统一 + 解码后落 CPU

## 6. 顺带确认"没问题的地方"

- `unload_all_models()` 在 DynamicVRAM 下**确实有效**（走 `partially_unload` → `vbar.free_memory`），
  不是空转 —— `model_management.py:2112` + `model_patcher.py:2043`
- "unload → gc.collect() → empty_cache" 的顺序是对的（反序收不回）
- OOM 一级自救（全卸 + 原参重试，`upscale.py:1608-1630`）符合"不静默降级"的既定语义
- `up_net.cpu()` 让放大网络退出 GPU（`nodes.py:1245`）—— 裸 Module 必须自己管，ComfyUI 看不见
- 3D 时序分块 + `attn=False` 是有效的省显存设计
