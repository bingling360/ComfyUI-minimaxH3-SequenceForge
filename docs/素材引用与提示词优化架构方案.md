## 0. 先把两件事说清楚

### 0.1 首尾帧：**是真实装的**，有代码为证

不是空壳。`nodes.py` 里的完整链路：

```
素材标「首帧图」→ chain_head_label → 首帧图片 = 加载该文件
素材标「尾帧图」→ chain_tail_label → 尾帧图片 = 加载该文件
        ↓
has_first_eff / has_end_eff   （也可能来自旧槽位 ds.first_frame / ds.end_frame）
        ↓
segments[i].frame_refs 决定"第 i 段是否参考首/尾帧"
缺省：首段参考首帧图、末段参考尾帧图
        ↓
video_vae.encode(...) → keyframe latent（head_frame_latent / end_frame_latent）
        ↓
注入 conditioning 的 keyframes（段头锚 / 段末锚）
```

所以它是**真的在改生成条件**，不是只改提示词文字。

**你觉得"怪异"的地方，我猜是这个**：打标入口在**素材库瓦片**上，
而"哪几段用它"的开关在**段卡设置**里 —— 两个地方，隔得远，
打完标不知道它落到哪了。

**改法（建议）**：段卡的「续接」组里直接显示
「本段首帧锚：`女主`（图）／尾帧锚：无」，并给一键跳转素材库。
让"打标 → 生效"这一条链在一处看得见。

### 0.2 引用体系：本轮已统一成 `@素材`

已经改完的（本次提交）：

| 项 | 之前 | 现在 |
|---|---|---|
| 提示词里引用 | `[[别名]]` | **`@别名`** |
| `@` 补全插入 | `[[别名]]` | **`@别名`** |
| 引用语模板（6 条） | `[[${l}]]` | **`@${l}`** |
| 后端解析 | 只认 `[[ ]]` | `@标签` + 旧 `[[标签]]`（老存档兼容） |
| 误伤防护 | — | `@` 带负向后顾，`a@b.com` 不会被当成标签 |

## 1. 提示词优化架构：现在的问题

### 1.1 现状链路

```
导演台段卡：用户写提示词（含 @别名）
        ↓  存进 ds.prompts[i] / segments[i].refs
执行期 nodes.py：
   _find_refs(文本) ∪ segments[i].refs   → label_order
   _apply_label_tokens(文本, label_order) → @别名 换成 <Picture 1>
   compose_base / compose_reference        → 官方三/六字段
        ↓
   送模型
```

另有 `tools/h3_prompt_expander`（独立工具）：把中文意图编译成官方三字段，**自带一套 compose 逻辑**。

### 1.2 三个真问题

| # | 问题 | 后果 |
|---|---|---|
| 1 | **编译结果不可见** | 用户写完提示词，要等执行才知道 `@女主` 变成了 `<Picture 1>`；编号顺序、有没有漏引，全靠猜 |
| 2 | **两套编译器** | `nodes.py` 的 `compose_*` 与 expander 各写一套，规则容易漂移（官方格式一直在小改） |
| 3 | **引用声明要手写** | 用了 `@女主`，但"女主是谁"得自己在提示词里描述；素材本身带的定义没被用上 |

## 2. 方案（照即梦 / LibLib 的思路）

### 批 1：段卡加「编译预览」（只读，风险最低）

段卡提示词框下面加一行可折叠的「编译预览」：

```
编译后：integrated_multimodal_description: [Shot 1] 夜晚便利店门口，
        <Picture 1> 撑着伞站立……
        （<Picture 1> = @女主）
```

- 纯前端就能做：把 `@别名` 按规则换成 `<Picture N>`（编号规则同 `nodes.py`）
- 用户立刻看到"我写的 @女主 最终会变成什么"
- **直接解决"编号看不懂 / 漏引用"**

### 批 2：编号顺序改成「按文本首次出现」

现在：编号顺序 = 勾选顺序 + 文本补充的顺序（两套混在一起）。

改成：**按提示词文本里 `@别名` 第一次出现的先后编号**。
即"先提到的先当 Picture 1"，符合直觉，也和预览一致。

> 段 refs 勾选仍保留 —— 它的作用是"声明本段要用哪些素材"（不写在正文里也能编译），
> 但不再影响编号顺序。

### 批 3：两套编译器合一

- `expander` 不再自带 compose 逻辑，改为调用 `prompts.py` 的 `compile_segment`
- `prompts.py` 成为**唯一的官方格式出口**（导演台 + expander + 执行期共用）
- 好处：官方格式再改，只改一处

### 批 4：素材引用自带声明（省手写）

素材在库里有描述（`desc`）和角色名（`alias`）。编译时**自动**把"引用到的素材"整理成最小声明：

```
<Picture 1>: 女主 —— 短发少女，米色风衣
```

用户不用再在正文里重复描述一遍；不想用的可以在段卡里关掉。

## 3. 建议的推进顺序

```
批 1（编译预览）  ← 立刻能感受到，且纯前端、零风险，建议先做
   ↓
批 2（编号按文本顺序）
   ↓
批 4（引用自带声明）    ← 批 1+2 做完，这一步才有意义
   ↓
批 3（两套编译器合一）  ← 改动最大，放最后
```
