## 二、面板展开说明（长文案）

### 为什么需要这一层

两个硬数字：UNET（int8，`hybrid_fl2va_ref2va_b25-49`）约 **20GB**、文本编码器（int8）**25.3GB**。
**任意一坨单独就超过 16GB 内存。**

所以这里说的不是「某一瞬间要同时装 45GB」。它是判据
`R_m = (UNET + TE) ÷ 内存总量` 的结论：**内存装不下其中任何一坨，两坨都留不住**。
表现不是「安静地落到磁盘」，而是**反复重读**——跑 TE 时 UNET 的页被丢，跑 UNET 时 TE 的页被丢。
项目在 12GB 卡上的实测就是这个症状：`R_v 1.66 · R_m 2.16`，**每步要重读 8.9GB（46% 的权重）**。

**顺带澄清一个常见误解：ComfyUI 的「卸载」不等于「搬到磁盘」。**

- `unload_all_models()` 释放的是**显存**上的权重复本，CPU 侧那份还留着——这是 smart memory
  的缓存设计（为了回载快），不是内存泄漏。
- 想让权重真正从内存消失，要用 `--disable-smart-memory`；代价是每段都重新从磁盘读十几 GB。
- safetensors 权重大多是 **mmap 文件页**（项目实测口径：计入物理占用、**不计入 commit**）。
  这类页被系统回收时**直接丢弃**——磁盘上本来就有原文件，**不需要写 pagefile**。

**真正吃 pagefile 的是匿名内存**：帧张量、采样激活、LoRA patch 后的副本、Python 堆。
项目实测 `torch.cat` 拼 8 段全链帧的峰值是 **19.8GB**（D3）；诊断日志里
「32GB 内存可用只剩 5GB、pagefile 36GB 已用掉一半」就是这么来的。

**但 pagefile 还是得管**：它太小的时候，匿名内存要不到，后果是
`DefaultCPUAllocator: can't allocate memory` / 「无法提交内存」，渲染当场断掉。
所以它既是**性能保底**，也是**可用性上限**。

### 为什么不靠「先跑 TE、再卸掉、再上 UNET」

单段场景下这个思路是对的，也确实更省内存。但本项目的主场景是**多段链**（典型 8 段），
而 TE 在链里**每段都要真正前向**：

- `cond_cache.py` 的 `CachedClipProxy` 就是为「同一段提示词只编码一次」而写的；
- 它此前**命中恒为 0**（官方 H3 节点固定给 `tokenize` 传一个 list、空表也传，`hash([])`
  抛 TypeError → 全部旁路）。**2026-09-24 已修**：换成类型白名单归一化后，
  「无首帧图、无参考素材」的段在二采那次不再重算，**每段省 1 次**；
  挂了首帧图或参考素材的段仍然旁路（它们两次的输入真的不同，必须重算）。
- 即便如此，**一采那一次必然是真前向**（首次编码，缓存里没有）。

于是「用完即卸」= **每段重载 25.3GB 的 TE**，比让它常驻更慢。两坨权重在内存里共存，
是这个场景下的**稳态选择**，不是物理必然——这也正是判据用「合计」口径的原因：
它算的是稳态容量，不是峰值瞬间。

### Windows：怎么改 pagefile

**推荐用图形界面（最稳，所有版本一致）**

1. `Win + R` → 输入 `sysdm.cpl` → 回车
2. `高级` 选项卡 → `性能` 区域的 `设置`
3. 再切到 `高级` 选项卡 → `虚拟内存` 区域的 `更改`
4. **取消勾选**「自动管理所有驱动器的分页文件大小」
5. 选中一个 **SSD 所在的盘** → 选 `自定义大小`
6. 初始大小 / 最大值按下面的建议填 → 点 `设置` → 确定
7. **重启电脑**（不重启不生效）

**如果更习惯命令行**

- 旧系统（Win11 24H2 起 WMIC 默认已移除）：
  `wmic pagefileset where name="C:\\pagefile.sys" set InitialSize=32768,MaximumSize=65536`
- 注册表方式（通用）：
  `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management`
  下的 `PagingFiles`，值格式为：`C:\pagefile.sys 32768 65536`（单位 MB）

> 注册表方式同样需要管理员权限，同样需要重启。

**填多少**

| 项 | 建议 |
|---|---|
| 起步值（16GB 物理内存） | 初始 **32768 MB（32GB）**，最大 **65536 MB（64GB）** |
| 盘够宽裕 | 初始 48GB / 最大 96GB |
| 所在盘 | **必须 SSD**。放机械盘等于把「变慢」升级成「卡死」 |
| 盘上留白 | 长期留 **≥ 100GB** 空余（项目的磁盘守卫也看这块盘） |

### Linux：怎么加 swap

```bash
sudo fallocate -l 64G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 开机自动挂载
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 关键：有物理内存时尽量别换出（默认 60 会过早换页）
sudo sysctl vm.swappiness=10
```

- `vm.swappiness` 才是「少换出」的正经旋钮，加 swap 的同时建议一起调。
- ⚠ **Linux 上没有 swap 不是「变慢」，是进程被 OOM killer 直接 SIGKILL** —— 连 `except` 都跑不到。
  这也是本项目落盘守卫在 critical 档直接禁止全卸的原因。

### 为什么这段只能靠你自己动手

1. 需要**管理员 / root** 权限；
2. 必须**重启**才生效；
3. 影响的是**整台机器**的配置，不是这个应用，插件无权也不该代改。

插件能碰的只有应用内、可随时回滚的旋钮（块交换、分块、腾挪强度、落盘守卫行为）。
